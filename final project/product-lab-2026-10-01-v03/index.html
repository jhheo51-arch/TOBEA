01 / OBSERVATION

사용자는 어디에서 멈출까요?

신청 여정

같은 집단 · 순서대로 진행한 인원

단계별 진행 인원을 보여줍니다. 반복 방문 횟수는 포함하지 않습니다.

관찰 → 가설

숫자만으로 이유는 알 수 없어요.

설명이 부족했을 수도, 신청 의향이 낮았을 수도 있습니다. 실제 사용자에게 물어보거나 화면을 바꿔 시험해 보세요.

개선 가설 비교하기 →

집단을 나눠서 보면

완료율 = 신청 완료 인원 ÷ 방문 인원
집단방문신청 완료완료율

집단별 차이는 기기 때문에 생겼다고 단정할 수 없습니다. 유입 경로와 이용 목적도 확인해야 합니다.

데이터 기준과 한계 보기

각 숫자는 같은 분석 기간·같은 사용자 집단에서 순서대로 해당 단계에 도달한 고유 인원이어야 합니다. 현재 예시는 기기별 집단이 겹치지 않는다고 가정합니다. 직접 입력한 숫자의 출처·중복·기간 일치는 자동 검증하지 않습니다.

02 / DECISION

무엇을 먼저 바꿀까요?

판단은 여러분이, 계산은 실험실이.

영향 × 근거 확신 ÷ 노력으로 비교합니다. 점수는 여러분의 판단을 정리하는 도구이며, 예상 성과가 아닙니다.

03 / EXPERIMENT

선택을 검증할 계획을 만드세요.

실험 준비 단계

%p는 비율의 차이입니다. 25% → 30%는 +5%p입니다. 실제 비교 실험의 기간·표본 수는 별도로 설계해야 합니다.

가정해 보기

이 단계가 조금 나아진다면?

선택한 단계 이후의 진행률과 유입 인원이 그대로라는 가정입니다. 인과관계나 실제 개선 효과를 예측한 결과가 아닙니다.

AI 에이전트 · 사람의 선택으로 반영

아래 AI 제안을 확인하고 채택할 수 있습니다. 같은 모델의 검토는 실제 개선 효과를 증명하지 않습니다.

04 / AI ASSISTANT

근거를 연결한 개선 가설 만들기

서버 설정 확인 중…

현재 선택한 집단의 단계별 인원·자료 구분·점검 수치와 위 목표만 전송합니다. 집단 이름과 원본 사용자 식별자는 전송하지 않습니다. 목표에도 개인정보를 쓰지 마세요.

전송할 자료 확인
반영 전 기존 기획을 보관합니다. 점수와 선택 이유는 직접 작성하세요. 검토 보류 결과는 반영할 수 없습니다.
분석 보관 파일
현재 분석과 이전 분석을 JSON 보관 파일로 내려받고, 다른 브라우저에서 복원할 수 있습니다. 원본 행동 기록과 API 키는 포함하지 않습니다.
파일 대신 보관 내용 붙여넣기

  
Product Lab · 숫자에서 관찰을, 관찰에서 실험을.AI 실행 동의 시 집계 수치와 목표를 OpenAI로 전송합니다.




분석할 숫자 입력
같은 기간·같은 집단이 순서대로 진행한 인원만 입력해 주세요. 현재 분석은 이전 분석 보관함에 남기고 새 분석을 시작합니다.


사용자 행동 자료 가져오기
CSV는 쉼표로 열을 구분하는 표 파일입니다. 이 브라우저 안에서만 읽습니다. 이름·이메일 대신 익명 식별자를 사용해 주세요. 최대 2MB·10,000개 기록입니다.
파일 대신 CSV 내용 붙여넣기
기간 안의 첫 방문 기기로 집단을 정하고, 기간 안에서 순서대로 진행한 인원을 계산합니다. 동일 시각 기록은 다음 단계 순서의 증거로 사용하지 않습니다. 종료 직전 방문자는 완료할 시간이 짧을 수 있습니다.
