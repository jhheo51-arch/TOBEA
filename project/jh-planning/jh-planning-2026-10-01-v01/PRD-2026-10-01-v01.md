# JH 기획 — 제품 기획서(PRD) v01

- 작성일: 2026-10-01
- 상태: 구현 전 초안. 첫 고객과 실제 수요는 미확인.
- 프로젝트: 홍보·브랜딩 기획 파트너 웹 서비스
- 한 줄 소개: “무엇을 왜 알려야 할지부터, JH 기획이 함께 정리합니다.”
- 이름: 사용자가 제안한 ‘JH 기획’을 작업명으로 사용. 상표·도메인 사용 가능 여부는 조사하지 않음.

## 1. 요청과 설계의 근거

사용자는 홍보·브랜딩을 대신해 주는 프로젝트를 만들고, PO/PM(제품의 문제·우선순위·진행을 책임지는 역할)과 사업기획 직무의 역량을 보여주고 싶어 한다. 중심 질문은 “무엇을 왜 해야 하나?”이며, 활용 문서는 문제 정의·지표·문서로 구성한다.

첫 이미지의 기획 직무 표를 기획 구조의 기준으로 사용한다. 두 번째 이미지의 ‘AI 에이전트 또는 웹 제품 만들기’, ‘배운 내용 적용’, ‘스스로 판단하고 그 판단 정리’, ‘결과 검증’을 프로젝트 방향에 반영한다. 이미지에 적힌 공개 GitHub 제출·다른 사람 태그는 참고 과제 조건이다. 실제 공개 범위와 제출은 이후 사용자가 결정한다.

## 2. 사업 방향과 제품 방향

**사업 방향:** 소규모 고객에게 브랜드의 전달 방향과 첫 홍보 실험을 정리해 주는 기획 대행 서비스.

**제품 방향:** 고객이 요청서를 작성하면 JH 기획 담당자가 문제·대상·메시지·성과 기준을 정리하고 실행 문서를 제공하는 웹 작업실. 웹 제품은 대행 업무를 빠르고 일관되게 수행하는 도구다.

**첫 서비스 묶음:** 고객 요청 정리 + 문제 정의서 1개 + 핵심 메시지 1개 + 채널 1개에 대한 홍보 초안 1개 + 성과 확인 계획 1개.

광고 집행·계정 운영·고객 메시지 발송·매출 보장은 첫 제공 범위에 포함하지 않는다. 실제 대행은 고객의 동의와 자료를 확보한 뒤 사람이 실행한다. 가격과 계약 방식은 수요 확인 후 정한다.

## 3. 첫 고객과 문제 가설

첫 고객은 **첫 상품 또는 서비스를 홍보하려는 소규모 브랜드·1인 사업자**로 가정한다. 이는 사용자 확정 사항이 아니며 개인 창작자나 행사 프로젝트로 변경할 수 있다.

- 상황 가설: 상품은 있지만 누구에게 어떤 장점을 알릴지 정리되지 않았다.
- 어려움 가설: 예쁜 소개나 게시물부터 만들면서 목적과 행동 유도가 모호해진다.
- 대안 가설: 직접 글 작성, 기존 양식 사용, 지인에게 요청, 전문 대행사에 의뢰한다.
- 제공 가치 가설: 실행 전에 대상·이유·다음 행동을 합의하면 홍보안의 방향을 판단하기 쉬워진다.

반복 수요·지불 의사·실제 고객 성과는 아직 확인하지 않았다. ‘대행사가 필요하다’는 결론을 미리 확정하지 않는다.

### 문제 정의서 구조

1. 누구인가: 대상 고객과 이용 상황.
2. 무엇이 막혔는가: 실제로 관찰하거나 들은 어려움.
3. 왜 중요한가: 영향을 받는 행동과 현재 손실.
4. 무엇을 알고 있는가: 출처가 있는 사실과 고객의 직접 설명.
5. 무엇이 가정인가: 아직 검증하지 않은 원인과 해석.
6. 무엇을 먼저 할 것인가: 이번에 선택한 실행과 제외 범위.
7. 어떻게 확인할 것인가: 예상 행동, 확인 기간, 성공·수정 기준.

## 4. 사용자 역할과 핵심 경험

- 고객: 홍보할 대상·목적·현재 상황을 설명하고 초안을 확인한다.
- JH 기획 담당자: 자료를 읽고 기획 초안을 수정하며 실행 우선순위를 정한다.
- 초기 시제품: 두 역할을 한 사람이 체험한다. 실제 다중 사용자 로그인·공유는 후속 범위다.

### 대표 이용 흐름

소개 화면 → 새 프로젝트 시작 → 고객 요청서 작성 → 문제 정의 → 메시지와 홍보안 작성 → 성과 확인 계획 → 담당자 검토 → 기획서 내려받기 → 실행 후 결과 기록 → 다음 버전 수정.

‘무엇을 왜 해야 하나?’에 답이 빠지면 실행 문서를 확정하지 않는다. 사용자가 빈칸을 이해할 수 있도록 구체적인 도움말을 제공한다.

## 5. 첫 구현 범위

첫 구현은 웹에서 체험할 수 있는 작은 제품(MVP: 핵심 가치부터 확인하는 첫 버전)으로 만든다.

| 기능 | 사용자에게 보이는 결과 | 완료 조건 |
|---|---|---|
| 브랜드 소개 | JH 기획의 대상·제공 문서·진행 과정·서비스 제외 범위 | 가상 실적이나 후기 없이 서비스 이해 가능 |
| 고객 요청서 | 브랜드명, 상품/서비스, 대상, 어려움, 희망 행동, 사용 채널, 근거 메모 | 필수값 누락 시 해당 항목 안내, 작성 중 저장 |
| 문제 정의 | 사실·가정·목표·우선순위·선택 이유를 정리하는 편집 화면 | 사용자가 각 내용을 수정 가능 |
| 브랜딩 방향 | 핵심 약속, 근거, 전달 말투, 핵심 메시지 | 출처 없는 강점·실적은 가정으로 표시 |
| 홍보 실행안 | 채널 1개, 홍보 문구 1개, 다음 행동, 일정, 담당자 | 메시지와 목적의 연결을 확인 가능 |
| 지표 계획 | 시작값, 목표값, 계산법, 측정 기간, 자료 출처, 판단 기준 | 미측정 시작값은 ‘미확인’, 0으로 자동 처리하지 않음 |
| 문서 내보내기 | 문제 정의서·브랜딩 방향·실행안·지표가 포함된 기획서 | 읽기 쉬운 문서 다운로드 및 인쇄 가능 |
| 결과 기록 | 실행 여부, 실제 수치, 고객 반응, 다음 수정 이유 | 가상 예시와 실제 결과 집계 분리 |

첫 버전에는 실제 AI 호출을 넣지 않는다. 입력을 정리해 주는 양식과 규칙 기반 초안을 먼저 구현하고, 자동 초안은 ‘양식 기반 초안’으로 표시한다. 담당자 검토 후 확정한다.

## 6. AI 확장 설계

실제 AI 연결은 첫 체험에서 필요성이 확인되면 추가한다. AI를 추가할 경우 ‘자료 읽기 → 초안 제안 → 누락·모순 검토 → 사용자 확정’으로 역할을 나눈다.

- 입력: 고객이 제공하고 전송을 허용한 요청서와 근거 자료만 사용.
- 출력: 문제 가설, 메시지 후보, 홍보 초안, 지표 제안.
- 검토: 원문 근거, 사실/가정 구분, 목표와 지표의 연결, 실행 범위 점검.
- 승인: 사용자가 수정·확정한다. 게시나 발송을 자동 수행하지 않는다.
- 실패 처리: 응답 실패 시 기존 입력 보존, 양식 작성 계속 가능, 재시도 안내.
- 비용·시간: 실제 호출 수와 응답 시간 기록. 운영 예산과 사용할 모델은 연결 시 정한다.

AI가 없는 첫 버전은 ‘웹 제품’으로 설명한다. 실제 연결 전 ‘AI 에이전트가 운영한다’고 홍보하지 않는다.

## 7. 화면과 브랜드 표현

- 첫 화면: JH 기획 로고형 문자, 한 줄 소개, ‘내 브랜드 기획 시작하기’, 제공 문서 미리보기.
- 요청서: ‘어떤 브랜드인가요?’, ‘누가 관심을 가지면 좋을까요?’, ‘무엇을 하게 만들고 싶나요?’ 등 쉬운 질문.
- 기획 작업실: 문제 정의 → 브랜딩 방향 → 실행안 → 지표 → 최종 문서 순서. 진행 상태와 저장 상태 표시.
- 결과 화면: 이번 선택과 이유, 확인할 행동, 문서 다운로드, 실행 후 기록 진입.
- 표현 방향: 신뢰감 있는 짙은 남색·밝은 배경·한 가지 강조색. 이는 디자인 초안이며 사용자의 색상 선호는 미확인.
- 읽기 편한 한글, 명확한 입력 항목 이름, 키보드 조작, 모바일 한 열 배치를 기본으로 한다.

단순한 대행사 소개 화면으로 끝나지 않도록 실제 기획 문서를 만드는 경험을 중심에 둔다.

## 8. 지표 설계

### 제품 자체의 성공 확인

핵심 지표는 **실제 체험자가 자신의 상황으로 작성하고 검토·내보내기까지 완료한 기획서 수**다. 다운로드만으로 유용함이나 홍보 성과를 판단하지 않는다.

| 지표 | 정의·계산법 | 확인 목적 |
|---|---|---|
| 기획 완료율 | 필수 항목 검토 후 내보낸 실제 프로젝트 수 / 작성을 시작한 실제 프로젝트 수 | 작성 흐름이 끝까지 이어지는지 |
| 작성 시간 | 작성 시작부터 검토 완료까지의 시간, 중단 여부 함께 기록 | 부담이 큰 단계가 있는지 |
| 방향 설명 가능 여부 | 체험자가 ‘누구에게·무엇을·왜·어떤 행동을’ 설명하는지 관찰 | 기획 방향이 명확해졌는지 |
| 실제 활용률 | 실제 실행에 문서를 사용했다고 확인한 프로젝트 수 / 완료 프로젝트 수 | 문서가 실제 행동으로 이어지는지 |
| 수정 이유 기록률 | 근거와 수정 이유가 있는 수정 프로젝트 수 / 전체 수정 프로젝트 수 | 판단 과정이 남는지 |

분모가 0이면 비율은 ‘자료 없음’으로 표시한다. 연습·가상 예시를 실제 사용자 지표에 포함하지 않는다. 첫 버전의 기기 내 기록은 전체 고객 통계를 대표하지 않는다.

### 고객 홍보의 성공 확인

고객이 바라는 행동에 따라 지표를 하나 우선 선택한다. 문의가 목적이면 실제 문의, 예약이 목적이면 완료 예약을 확인한다. 단순 조회수는 참고 지표다.

예시(가상): ‘상품을 이해한 방문자가 문의 버튼을 누르게 한다’ → 클릭률 = 문의 버튼 클릭 수 / 해당 페이지 방문 수. 클릭과 실제 문의는 구분한다. 외부 채널 수치는 고객이 직접 입력하며 자동 수집된 것처럼 표시하지 않는다.

모든 지표에는 측정 기간·현재값·목표값·출처·변경 판단 기준이 있어야 한다. 과거 자료가 없으면 첫 기간에 시작값을 측정한다. 홍보 전후 수치 차이만으로 인과관계를 확정하지 않는다.

## 9. 초기 검증 계획

아래 인원과 기준은 계획이며 이미 검증한 결과가 아니다.

1. 준비 조사: 첫 고객 후보 3명에게 최근 홍보 상황, 실제 어려움, 사용 중인 대안을 확인한다. 대행 서비스가 필요하다는 방향으로 답을 유도하지 않는다.
2. 사용성 확인: 대상에 맞는 체험자 3명이 자신의 자료로 요청서부터 문서까지 작성한다. 막힌 위치, 도움 횟수, 문서 수정 이유를 기록한다.
3. 잠정 통과 기준: 3명 중 2명 이상이 진행자의 입력 대행 없이 기획서를 완성하고 대상·메시지·행동을 설명한다. 소수 결과로 시장 수요를 확정하지 않는다.
4. 실제 활용 확인: 동의한 고객 1건에서 한 채널의 작은 실행을 해 보고 출처가 있는 결과를 기록한다. 가격·유료 의뢰 의사는 별도로 확인한다.
5. 수정 기준: 요청서 질문을 이해하지 못하면 질문 수정, 결과가 일반적이면 근거 입력 보강, 실제 활용이 없으면 제공 범위·대상 재검토.

## 10. 저장·오류·개인정보

- 첫 버전은 현재 브라우저에 프로젝트를 저장한다. 기기나 브라우저를 바꾸면 자동으로 이어지지 않으며 브라우저 자료 삭제 시 사라질 수 있다.
- 별도 저장 서버, 실제 계정 로그인, 고객 간 문서 공유는 후속 범위.
- 저장 실패 시 성공으로 표시하지 않고 다운로드로 보존할 수 있도록 안내한다.
- 날짜·숫자 오류, 필수값 누락, 실제 결과와 예시 혼동을 화면에서 안내한다.
- 사용자 입력은 문자로 안전하게 표시하여 입력 내용을 화면 실행 코드로 해석하지 않는다.
- 비밀번호·인증값·불필요한 연락처를 받지 않는다. 실제 고객 자료와 공개 예시는 구분한다.
- 공개 제출에는 코드·가상 예시·검증 범위만 포함하는 것을 기본 후보로 두되 실제 업로드는 사용자가 결정한다.

## 11. 구현 순서와 완료 판단

1. 이번 단계: PRD 초안 작성, 첫 고객·제공 가치 확인.
2. 다음 단계: 새 버전 폴더에 소개 화면·요청서·문서 작성 흐름 구현.
3. 기능 확인: 빈칸 안내, 저장·새로고침 복원, 편집, 다운로드, 예시/실제 분리, 좁은 화면 확인.
4. 체험 후 개선: 개선 후보 3개를 비교하고 하나의 선택 이유와 변경 결과를 작업일지에 기록.
5. 제출 준비: 실행 방법·실제 검증·미검증 범위를 정리한 README 작성. 공개 저장소와 발표 자료는 필요한 시점에 결정.

첫 구현 완료는 ‘가상 예시와 자신의 입력으로 요청서 → 기획 → 지표 → 문서 다운로드를 실제로 사용할 수 있는 상태’다. 실제 고객 효과와 유료 대행 사업의 성립은 별도 검증 대상이다.

## 12. 이번 설계의 판단과 미정 사항

| 판단 | 선택 이유 | 현재 상태 |
|---|---|---|
| 소개와 기획 작업실 결합 | 대행사 브랜드와 기획 직무의 실제 결과물을 함께 보여줌 | 설계 제안 |
| 소규모 브랜드를 첫 대상으로 가정 | 첫 상품·한 채널·한 행동으로 범위를 좁히기 쉬움 | 사용자 선택 대기 |
| 문서 3축: 문제·지표·실행 | 사용자의 직무 방향과 ‘무엇을 왜’ 질문에 직접 연결 | 요청 반영 |
| 한 채널·한 실행부터 제공 | 실행 이유와 결과를 비교할 단위를 작게 유지 | 설계 제안 |
| 웹 제품 먼저, AI 연결 이후 | 문서의 가치와 작성 흐름을 먼저 체험 가능 | 설계 제안 |

미정: 확정 고객 유형, 사용자의 실제 홍보·브랜딩 경험과 강점, 첫 실제 고객 자료, 선호 디자인, AI 연결 필요성, 가격, 공개 범위.

지금 필요한 선택은 첫 고객 유형 하나다. 나머지는 작은 제품을 체험하며 단계별로 구체화한다.
