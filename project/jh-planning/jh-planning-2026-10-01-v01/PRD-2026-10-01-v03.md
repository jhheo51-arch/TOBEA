# JH 기획 — 제품 기획서(PRD) v03

작성일: 2026-10-01. 상태: 설계 수정, 구현 전.

이번 버전은 오른쪽 첨부 이미지의 과제 목표와 기존 프로젝트 차별점을 기준으로 v02를 보완한 최신 설계다. v01·v02는 보존한다. 기존 입력·저장·접근성·오류 처리의 상세 요구는 v02를 참고하되, AI를 나중으로 미루는 범위는 이번 버전으로 대체한다.

## 1. 목적과 방향

**JH 기획은 다양한 산업의 홍보 의뢰를 받아 전략을 비교하고, 선택 이유를 반영한 홍보 결과물과 검증 계획을 만드는 AI 기획 대행 웹 작업실이다.**

산업 하나로 고객을 제한하지 않는다. 브랜드·상품·서비스·행사·개인을 공통 구조로 다루며, 중심 질문은 ‘무엇을 누구에게 왜 알리고, 어떤 행동을 이끌 것인가?’다.

PO/PM은 제품의 문제와 우선순위·진행을 책임지는 역할이다. 이 프로젝트에서는 예쁜 소개 화면뿐 아니라 문제 정의·자원 배분·전략 선택·성과 기준·결과 문서를 통해 기획 역량을 보여준다.

## 2. 기존 프로젝트와의 차별점

비교 근거: PROOFLINE v13 PRD·README, FANBRIDGE v03 PRD·최신 시제품 소개. JH 기획은 아래 기능을 설계하는 단계이며 아직 구현 성과가 아니다.

| 기준 | PROOFLINE | FANBRIDGE | JH 기획 |
|---|---|---|---|
| 출발점 | 개인의 경험·강점 후보 | 팬의 실제 질문·공식 정책 | 고객의 홍보 의뢰·브랜드 자료·사업 목적 |
| 핵심 질문 | 내 경험으로 누구에게 어떤 도움을 줄까? | 안내를 이해하고 올바르게 행동할 수 있을까? | 무엇을 왜 홍보하며 어떤 전략을 선택할까? |
| 핵심 판단 | 경험을 작은 서비스 제안으로 연결 | 우선 개선할 안내 문제 선택 | 전략 대안·작업량·제약 비교와 자원 배분 |
| 결과물 | 방향 카드·서비스 제안·반응 요약 | 개선 안내·응대 가이드·비교 시험 | 전략 비교표·브랜딩 방향·홍보 실행물·측정 계획·결과 보고 |
| 검증 | 실제 제안 후 관심·참여 등 반응 | 과제 정답·시간·도움·중단 비교 | 목표와 전략의 연결·실행물 품질·실제 홍보 행동 결과 |
| 적용 범위 | 개인과 첫 도움 대상의 상황 | 삼성 팬의 좁힌 조건 | 산업 선택을 강제하지 않는 공통 의뢰 구조 |

문제 정의·제안·반응 기록·문서화는 공유한다. 범용 양식과 이름만 바꾸면 차별점이 약하다. JH 기획의 필수 차별 기능은 **전략 대안 비교 → 담당자 선택 → 홍보 실행물 제작 → AI 검토·수정**이다.

## 3. 고객과 문제 가설

공통 고객: 알릴 대상은 있지만 누구에게 어떤 가치를 전달하고 어떤 행동을 이끌지 정리할 필요가 있는 사람·조직.

문제 가설: 게시물부터 만들면서 목적·근거·성과 기준이 모호해진다. 전략 대안을 비교하고 근거를 확인하면 실행 방향을 판단하기 쉬워질 수 있다. 반복 수요·지불 의사·실제 효과는 미확인이다.

산업·규모는 선택 입력이다. 업종만으로 고객 성향이나 홍보 채널을 확정하지 않는다. 산업별 전문성을 검증 없이 주장하지 않는다.

## 4. 핵심 경험과 문서

의뢰 입력 → 근거·누락 확인 → 문제 정의 → 전략 후보 비교 → 담당자 선택·이유 → 브랜딩 방향 → 홍보 실행물 → 측정 계획 → AI 검토·수정 → 담당자 최종 확인 → 문서 출력 → 실행 후 결과 기록.

- 문제 정의서: 대상·상황·막힘·왜 중요한지·확인된 사실·가정·이번 범위.
- 전략 비교표: 후보 3개와 근거·필요 자료·예상 작업량·비용 가정·제약·지표, 선택/제외 이유.
- 브랜딩 방향서: 핵심 약속·차별점과 근거·말투·핵심 메시지.
- 홍보 실행안: 채널 1개, 게시물 초안 1개, 홍보 페이지 구성안, 일정·담당자·다음 행동.
- 성과 계획·보고: 현재값·목표값·계산법·기간·출처·판단 기준·실제 결과·다음 수정.

후보는 의뢰별로 제안한다. 예를 들어 가치 설명·이용 장면·질문 해소를 비교할 수 있지만 모든 산업의 정답으로 고정하지 않는다. 근거 없는 시장 규모·예산·수익률을 만들어 쓰지 않는다.

## 5. 첫 제출 버전의 기능 완료 조건

| 기능 | 완료 조건 |
|---|---|
| 소개·범용 의뢰 | 업종 선택 없이 시작, 목적·대상·행동·근거·제약 입력, 저장 상태 표시 |
| 문제 정의 | 사실과 가정 구분, 부족한 정보는 질문하거나 미확인 표시 |
| 전략 비교·선택 | 후보 3개 비교, 사람이 선택과 이유 확정, AI 추천과 사용자 선택 구분 |
| 실행물 작성 | 선택 방향을 메시지·게시물·페이지 구성·지표에 일관되게 반영 |
| AI 검토·수정 | 누락·모순·근거 없는 주장 검토, 최대 2회 수정, 해결 안 된 항목 표시 |
| 수정 관리 | 목적·전략 변경 시 기존 실행물 재검토 표시, 이전 버전과 변경 이유 보존 |
| 문서 출력 | 문제·전략·지표·실행물·검토 상태를 내려받고 인쇄 가능 |
| 실제 결과 기록 | 작성/다운로드와 실제 실행 구분, 예시와 실사용 결과 분리 |
| 오류·보존 | 필수값·숫자 오류 안내, 저장·호출 실패 시 입력 보존, 성공으로 오표시하지 않음 |

첫 버전은 브라우저에 저장한다. 다른 기기로 자동 동기화되지 않으며 자료 삭제 시 사라질 수 있어 파일 내보내기를 제공한다. 사용자 입력은 화면 실행 코드로 해석하지 않는다. 키보드 조작·읽기 편한 한글·모바일 한 열 배치를 기본으로 한다.

## 6. AI의 자율 작업과 사람의 판단

AI가 이어 할 일: 의뢰 정리, 누락 탐지, 문제 가설과 전략 제안, 선택된 전략의 실행물 제작, 검토·수정, 결과 문서 작성. 여러 역할은 작업 단계이며 별도 모델이나 여러 에이전트를 반드시 뜻하지 않는다.

사람이 할 일: 실제 목적·제약·근거 제공, 필요한 질문 답변, 전략 선택 이유, 최종 결과 확인, 실제 게시·집행 결정, 실제 반응 자료 제공. 매번 지시하지 않아도 작업한다는 것은 사람의 판단까지 AI가 확정한다는 뜻이 아니다.

최초 입력과 전략 선택 후 허용된 작업은 이어 수행한다. 필수 정보 부족·근거 없는 주장·목표와 지표 불일치·호출 실패는 상태와 이유를 남기며 실행 준비 완료를 막는다. 검토·수정은 최대 2회로 제한한다.

실제 AI 연결을 제출 목표에 포함한다. 화면 개발 중 가상 응답은 시연이라고 표시하고 실제 작동 완료로 계산하지 않는다. 연결 전 사용할 자료의 전송 범위와 비밀 인증값 설정을 확인한다. 실제 호출 수·시간·사용량과 확인 가능한 비용을 기록한다.

같은 AI의 초안과 검토는 독립 사실 검증이 아니다. 확인하지 못한 사실은 미확인으로 남긴다. 게시·광고 결제·고객 메시지 발송은 자동 수행하지 않는다.

## 7. 지표와 검증

제품 지표: 실제 프로젝트의 기획 완료율, 작성 시간·중단, 체험자의 대상/메시지/행동 설명 여부, 실제 문서 활용, 근거 있는 수정 이유. 완료율은 완료 프로젝트/시작 프로젝트로 계산하며 분모 0은 자료 없음이다.

홍보 지표: 목적에 맞는 실제 문의·예약·신청·의뢰 등 하나를 우선 선택한다. 조회·클릭과 실제 문의를 구분한다. 현재값·목표값·계산법·기간·출처·수정 기준을 기록한다. 미측정은 0으로 처리하지 않는다. 수작업 입력을 자동 수집으로 표시하지 않는다.

시험 계획(아직 수행하지 않음):

1. 서로 다른 산업·활동 맥락 3개 이상으로 의뢰→전략→제작→검토→문서 흐름 시험. 가상 의뢰는 가상 표시.
2. 정보 부족·상충된 목표·근거 없는 주장·호출 실패·저장 실패 조건 시험.
3. 관련 체험자 3명에게 자신의 상황으로 작성하게 하며 막힌 단계·도움·수정 이유 관찰. 잠정 기준은 2명 이상이 입력 대행 없이 완료하고 방향을 설명하는 것.
4. 동의한 실제 고객 1건에서 작은 실행 후 출처 있는 반응 기록. 실제 고객 확보와 효과는 프로그램 검사만으로 확인할 수 없다.

소수 사례를 전체 산업으로 일반화하지 않는다. 전후 수치 차이만으로 홍보의 인과 효과를 확정하지 않는다.

| 과제 목표 | JH 기획에 반영할 일 | 남길 증거 |

| 배운 내용 정리·적용 | 문제 정의·지표·문서·AI 역할·검토 기준 연결 | PRD·기능별 검증 결과 |
| 스스로 판단하고 판단 정리 | 대안·선택/제외 이유·변경 이유 | 사용자 판단과 AI 제안 구분 |
| 자신의 범위를 넘어 도전 | 허용 범위에서 AI가 제작·검토·수정 이어 수행 | 단계별 작업·중단·수정 기록 |

| 스스로 검증하게 만들기 | 코드 검사·실제 화면 시험·문서 누락/모순 검토 | 통과·실패·수정 결과와 한계 |

| 발표·포트폴리오 | 문제→판단→실행→결과·실패 설명 | README 필수, PPT/PDF 선택 |

GitHub 저장소는 프로그램 코드와 문서를 보관하는 공간이다. 공개 제출을 목표로 준비하되 실제 고객 자료·개인 기록·비밀 인증값은 공개 대상에서 제외한다. 이번 설계 수정에서 업로드·제출 메시지는 실행하지 않는다.

제출 준비 완료: 실제 AI 흐름, 전략 선택 기록, 실행물·지표·검토 문서, 서로 다른 맥락과 실패 조건 시험, 저장·오류·출력 검사, 실행 방법과 검증 한계가 있는 README, 공개 가능한 코드가 준비된 상태.

실제 홍보 효과 검증: 실제 고객·실행·측정 자료가 있어야 완료. 제출 준비가 끝나도 이 부분은 미검증일 수 있다. 계획 인원이나 목표 수치를 달성한 실적으로 표시하지 않는다.

## 9. 구현 순서와 설계 판단

1. 범용 의뢰·근거 입력과 프로젝트 보존.
2. 핵심 차별 화면인 전략 비교·선택 이유.
3. 선택 방향에 따른 브랜딩·홍보 실행물·지표 문서.
4. 실제 AI 제안·제작·검토·수정 연결과 오류 처리.
5. 산업이 다른 가상 의뢰와 실패 조건 시험, 수정.
6. 판단 기록·검증 결과·한계를 README로 정리해 공개 제출 준비.

검토한 방향: 범용 양식 유지, 대행사 소개 강화, 전략 비교·실행물·AI 검토 강화. 세 번째를 선택한 이유는 ‘무엇을 왜’라는 기획 판단과 오른쪽 이미지의 자율 작업·검증 도전을 실제 경험으로 보여주기 때문이다. 이는 설계 판단이며 사용자가 기능 세부를 확정한 것은 아니다.

다양한 산업을 아우르는 콘셉트와 오른쪽 이미지의 목표 준수는 사용자 요청으로 확인했다. 실제 고객 자료·가격·선호 디자인·AI 설정과 자료 전송 범위·공개 파일은 아직 구체화 전이다. 현재는 PRD까지 작성했으며 코드 구현·AI 연결·과제 제출은 아직 수행하지 않았다.
