# JH 기획 · 출근길 금융앱 리워드 사례 v03

2026-10-02. v02의 디자인·페이지 이동·기록 구조를 유지하고 실제 경험 기반 조사 초안을 추가했습니다. 이전 버전은 보존했습니다.

## 확인 방법

http://127.0.0.1:8784/ 를 새로고침하고 메뉴의 **출근길 금융앱 리워드 경험 개선**을 선택합니다. 문제 정의 → 방향과 선택 → 성공 지표 → 최종 문서에서 초안을 확인합니다. 사용자 검토 전이므로 문서를 확정하지 않았습니다.

실행 폴더에서 `python -m http.server 8784 --bind 127.0.0.1`로 시작합니다. 같은 주소와 브라우저를 유지해야 기존 기록에 접근할 수 있습니다. 기록은 각 브라우저에 따로 저장됩니다.

## 포함한 내용

- 사용자 자기보고: 출근 중 카카오뱅크·카카오페이·우리은행·신한은행 앱 리워드를 매일 이용함. 현재 표본 1명.
- 불편, 시간, 보상 금액, 신규 유입 효과, 지속 이용 효과는 미확인으로 구분.
- 전략 후보: 실제 흐름 관찰 / 혜택 안내 개선 / 보상 이후 기능 연결. 근거를 먼저 얻기 위해 관찰 선택.
- 관찰 계획: 5회 출근에 앱별 1건, 최대 20건. 2026-10-05~09는 미확정 제안이며 결과가 아님.
- 이후 운영 자료를 확보했을 때 확인할 참여율·7일 재방문율·추가 재방문자당 보상 비용 정의.

## 산출물

- `reward-plan-2026-10-02-v01.html`: 전체 조사 기획 초안과 빈 관찰 양식, 근거·미확인 사항. 인쇄 가능한 별도 문서.
- `reward-case-2026-10-02-v01.json`: 기존 서비스의 불러오기에 사용할 수 있는 초안 자료.
- `reward-case.js`: 새 버전 첫 방문 시 기존에 없는 사례 번호만 추가하는 데이터. 사용자가 수정한 동일 번호 기록은 보존.
- `reward-case-screen-v01.png`: Chrome 검증 시 문제 정의 화면.
- `build-case.cjs`: 산출물 생성용. 이미 생성된 파일은 덮어쓰지 않으므로 재실행하지 않아도 됨.

공개 참고 자료는 [카카오뱅크 공식 틴즈보너스 안내](https://blog.kakaobank.com/posts/saving-cashback-draw)(2026-03-27). 과거 청소년 대상 행사로 구분하며 현재 참가자가 이용하는 혜택과 동일하다고 판단하지 않습니다. 네 앱의 현행 화면·정책 전체를 조사한 자료는 아닙니다.

## 확인한 범위

`node check.cjs`, `node verify-case.cjs` 통과. 기존 기록 보존, 중복 추가 방지, 손상 원본 보존, 저장 실패 복구, 50개 한도, 초안 데이터 형식 확인. Chrome 화면에서 새 프로젝트와 문제 정의 항목을 확인했습니다. 기존 앱 내 브라우저 연결은 도구에서 사용할 수 없어 동일 주소의 Chrome 검증으로 대체했습니다. 앱 내 브라우저의 새로고침 결과는 참가자 확인 전입니다.

실제 출근 관찰, 실제 신규 사용자 시험, 효과 측정, 금융앱 조작, AI 호출, 외부 공유·업로드는 수행하지 않았습니다. 이후 브라우저 연결이 끊겨 최종 문서 탭 추가 검증은 완료하지 못했습니다. 전체 문서는 기존 문서 생성 함수로 생성하고 데이터 검사를 통과했습니다.
