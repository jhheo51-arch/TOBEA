# ContextLens v08 제품 기획

## 목적

사용자가 공개 콘텐츠의 맥락과 대화 반응을 근거로 고객경험 가설을 세우고, 자신의 판단과 후속 관찰을 사례별로 축적합니다.

## 사용자 흐름

링크 입력 → 원문/표본 확인 → 분석할 사람과 접점 정의 → 댓글 원문 검토·자동 분류 정정 → 욕구 후보/제공물 선택 → 실제 변경과 관찰값 기록 → 같은 링크 재분석 및 시점 비교 → 자료 내보내기.

## 핵심 요구와 수용 기준

1. **검토 가능한 자동 분석**: 댓글별 자동 라벨을 유지하고, 사용자는 근거·반례·관련 낮음, 수정 분류, 판단 이유를 별도 기록합니다. 새로고침과 재분석 뒤에도 복구합니다.
2. **콘텐츠별 해석**: 음악 영상, 일반 영상, 뉴스에 서로 다른 욕구 후보와 제공물 제안을 사용합니다. 같은 신호가 수집 댓글 2개 이상일 때만 후보로 보여 줍니다. 직접 입력 자료는 일반 영상 제안을 기본으로 합니다.
3. **고객 정의**: 분석할 사람, 이용 단계·접점, 바꿀 수 있는 경험, 이번 질문을 먼저 적게 합니다. 빈 칸을 임의로 채우지 않습니다.
4. **실험과 축적**: 가설·변경·지표·전후 값·진행 상태·관찰 결과를 사례와 함께 저장합니다. 재분석 때 매 수집 시점의 원문·분석 결과를 보존하고 댓글 중복과 욕구 후보 겹침을 보여 줍니다.
5. **이동 가능한 자료**: JSON 내보내기에 모든 시점과 수동 기록을 담고, 요약에는 주요 수동 기록을 포함합니다.
6. **읽기 편한 글자**: 한국어와 영어가 섞인 댓글을 한 화면에서 읽을 수 있도록 Noto Sans KR을 우선 적용합니다. 제목·본문·댓글·입력칸의 굵기와 줄 간격을 구분하고, 글꼴이 없는 환경에서는 운영체제 글꼴로 대체합니다. 외부 글꼴 서버를 사용하지 않습니다.
7. **서비스 자체의 CX 개선 시험**: 저장된 같은 분석 자료로 기존 방식과 개선 방식을 시험합니다. 개선 방식은 제안 카드에서 근거 댓글로 바로 이동합니다. 익명 참가자는 10분 안에 근거 2개, 반례 1개, 20자 이상 가설을 제출합니다.
8. **사람의 판정과 결과 비교**: 종료 시각·선택 댓글·가설을 참가자별로 보존합니다. 검토자가 원문과 답변의 타당성 및 근거 없는 주장을 판정한 뒤에만 성공으로 집계합니다. 방식별 시작·제출·검토·성공 건수와 중앙 소요 시간을 표시하고 Markdown 사례 요약을 저장합니다.

## 사용성 시험의 판단 기준

- **성공:** 서로 다른 근거 댓글 2개와 별도 반례 댓글 1개, 20자 이상 가설을 10분 안에 제출하고 검토자가 타당하다고 판단하며 근거 없는 일반화가 없어야 합니다.
- **성공 표시:** 성공 건수의 분모는 시험을 시작한 전체 참가자입니다. 제출하지 않은 경우도 성공에서 제외하며, 별도로 제출·검토 건수를 함께 보입니다.
- **보조 지표:** 검토한 참가자의 제출까지 걸린 시간 중앙값.
- **품질 점검:** 표본 댓글 수를 전체 고객 비율로 말하거나 확인하지 않은 효과를 단정한 사례 수.
- **비교 조건:** 같은 저장된 수집 시점과 동일 과제를 사용합니다. 각 방식에서 약 5명 이상의 답변을 검토하기 전에는 비교를 잠정 관찰로만 다룹니다. 이 정도의 작은 비무작위 표본은 인과관계를 증명하지 않습니다.
- **집계 범위:** 화면의 전후 수치와 저장한 사례 요약은 선택한 수집 시점에 속한 기록만 포함합니다. 검토자가 적은 관찰 메모를 사례 요약에 함께 남깁니다.

## 저장과 범위

로컬 SQLite 파일 한 개에 링크별 사례와 수집 시점을 저장합니다. 자동 분석은 원자료를 수정하지 않습니다. 수동 정정은 별도 필드로 저장합니다. 개인 대화나 비공개 자료 업로드 기능은 범위에 포함하지 않습니다.

## 성공 확인 방법

실제 유튜브 링크 분석, 댓글 정정과 메모 저장 후 새로고침 복구, 두 번째 시점 비교, 뉴스·일반 영상 분류 단위 시험, JSON 파일 확인으로 검증합니다. 변화의 인과관계는 사용자가 별도 지표와 비교 조건으로 확인합니다.
글자 변경은 실제 화면에서 댓글 원문·입력칸·제목의 가독성과 375px 화면의 가로 넘침 여부를 확인합니다.
사용성 시험은 참가자를 대신한 가짜 성과를 만들지 않고, 시작·제출·검토·집계·보고서 저장의 기능을 시험용 격리 데이터베이스에서 확인합니다. 실제 참가자 결과가 쌓이기 전에는 개선 효과를 입증했다고 표시하지 않습니다.
