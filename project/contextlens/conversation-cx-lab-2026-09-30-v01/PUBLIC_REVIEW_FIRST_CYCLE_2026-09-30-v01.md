# 첫 회차 준비: 공개 리뷰·댓글로 CX 문제 후보 찾기

작성일: 2026-09-30 · 참가자가 고른 자료 종류: 공개 리뷰·댓글 · 분석 대상 서비스: 아직 선택 전

## 이번 단계의 목표

공개된 글에서 **여러 작성자에게 나타나는 비슷한 어려움**과 각 글의 **목표·상황·해결 시도**를 찾는다. 리뷰만으로 실제 고객 여정 전체, 같은 사람의 재문의, 문제의 실제 발생률이나 해결 여부를 확인했다고 주장하지 않는다.

## 수집 기준 초안

1. 먼저 서비스 하나와 공개 게시 장소 하나를 정한다. 첫 후보는 앞서 본 공고와 연결되는 **토스 앱의 한국 App Store 공개 리뷰**다. [앱 페이지](https://apps.apple.com/kr/app/%ED%86%A0%EC%8A%A4/id839333328)
2. 수집 시작 날짜, 화면에서 보이는 정렬 방식, 검색·필터 조건을 기록한다. 가능하면 특정 별점이나 키워드를 먼저 고르지 않고 **화면에서 접근 가능한 최근 작성 리뷰를 순서대로** 모은다.
3. 목표는 작성 내용이 있는 리뷰 30건으로 두되, 접근 가능한 수가 적으면 실제 확인한 건수만 쓴다. 별점만 있고 글이 없는 평가는 맥락 분석에서 제외한다.
4. 사건당 공개 날짜, 별점, 글의 익명 요약, 사용자가 하려던 일, 막힌 상황, 서비스의 답변 유무, 확인 가능한 후속 결과, 출처 주소를 기록한다. 작성자 이름과 개인 정보는 결과물에 옮기지 않는다.
5. 같은 문제가 여러 리뷰에 등장하는지 세되 `해당 유형 리뷰 수 / 분석한 글 있는 리뷰 수`로 표기한다. 이는 **검토한 리뷰 내 비중**이며 전체 고객의 문제 발생률이 아니다.

## 첫 분류 기준 초안

| 질문 | 기록 예시 | 조심할 점 |
|---|---|---|
| 고객이 하려던 일은? | 송금하기, 카드 사용하기, 정보를 확인하기 | 기능 이름만으로 목적을 추정하지 않는다. |
| 어디서 막혔나? | 화면 탐색, 오류, 상태 확인, 안내 이해, 정책 제한 | 한 리뷰에 여러 문제가 있으면 주·부 유형을 구분한다. |
| 실제 경험은 무엇인가? | 오류를 겪었다는 진술, 찾지 못했다는 진술 | 회사 내부 오류 기록이나 사실 확인과 다르다. |
| 어떤 응답을 받았나? | 공개된 개발자 답변, 도움말 안내 | 공개 답변이 실제 해결을 뜻하지 않는다. |
| 이후 결과는? | 리뷰에 명시된 경우만 기록 | 말이 없으면 ‘결과 미확인’으로 둔다. |

## 이 자료로 낼 수 있는 결론

- 가능: 반복적으로 **언급된 문제 후보**, 그 글에 드러난 사용 맥락, 도움말·화면 개선 가설.
- 아직 불가: 전체 고객의 문제 발생률, 상담 SLA·CSAT, 같은 고객의 재문의율, 챗봇 실제 해결률, 개선 후 문의 감소.
- 다음 검증: 선택한 문제 하나의 공개 도움말·화면을 확인하고, 동의받은 사람에게 가상 과제를 수행하도록 해 개선 전후의 과제 성공과 혼란 지점을 본다.

## 출처 확인

[Apple의 앱 평가·리뷰 안내](https://developer.apple.com/app-store/ratings-and-reviews/)는 별점과 서면 리뷰가 서로 다른 자료이며, 작성자가 리뷰를 수정할 수 있음을 설명한다. 공개 페이지에서 읽을 수 있는 글과 개발자만 볼 수 있는 관리 자료를 혼동하지 않는다. 결과물에는 리뷰 원문을 길게 옮기지 않고 익명 요약과 출처를 남긴다.

## 다음에 결정할 것 하나

첫 분석 대상을 **토스 앱**으로 할지, 본인이 더 관심 있는 다른 서비스로 할지 정한다. 대상이 정해지면 실제 공개 리뷰를 읽고 수집 가능한 범위부터 확인한다.
