# ContextLens: 공개 대화 분석에서 개선 실행·검증까지

**문서 상태: 기획·구현 사례 초안. 실제 사용자에게서 얻은 개선 성과는 아직 없음.**

## 프로젝트 목적과 역할

CX 관련 실무 경험을 스스로 축적하기 위해, 공개 콘텐츠의 맥락과 댓글 반응을 읽고 근거를 검토하며 개선 가설을 기록하는 도구를 기획했습니다. 기획·데이터 활용 역량을 보여주는 것을 목표로 했습니다.

- 나의 기여: 분석 대상과 목적 정의, 맥락을 먼저 읽는 흐름 요구, 근거·반례 검토와 기록 방향 결정, 모바일에서 세부 내용을 펼쳐 보는 방식 요청, 다국어 자료의 검토 범위 고려, 개선 효과를 측정할 대상으로 ContextLens 자체 선택.
- 도움받은 부분: Codex가 코드 작성과 기술 검증·배포를 수행했습니다. 구현된 기능의 확인과 실제 사용자 조사·결과 해석은 추가로 진행해야 합니다.
- 진행 형태: 개인 프로젝트. 실제 제품·운영 조직과의 협업 경험을 이 사례로 주장하지 않습니다.

## 문제 정의와 데이터의 역할

공개 댓글을 읽을 때 반복 표현만 세면 원문 맥락을 놓치거나 일부 반응을 전체 고객의 욕구로 일반화할 수 있습니다. 원문·표본 범위·반례를 함께 검토하고, 사람이 자동 분류를 수정한 이유를 남기도록 설계했습니다.

첫 개선 시험의 질문은 “제안에서 관련 댓글로 바로 이동할 수 있으면, 답변 품질을 유지하면서 근거 탐색의 부담이 줄어드는가?”입니다. 아직 실제 사용자의 불편 관찰로 확인하지 않은 문제 가설입니다.

이전에 선택한 유튜브 영상의 공개 댓글을 동일한 과제 자료로 사용할 수 있습니다. 영상 댓글은 ContextLens 사용자의 불편을 직접 보여주는 자료가 아닙니다. 앱의 불편 근거는 실제 참가자의 행동·응답·관찰 메모에서 확보합니다.

## 판단과 실행

| 결정 | 이유 | 구현 내용 |
| --- | --- | --- |
| 맥락을 먼저 확인 | 반응이 어떤 콘텐츠에서 나온 것인지 확인하기 위해 | 본문 확보 상태·맥락·수집 한계 표시 |
| 최신순·인기순을 나눠 읽기 | 정렬에 따라 노출되는 반응이 다르기 때문에 | 정렬별 표본·중복과 고유 댓글 표시 |
| 자동 분류와 사람 판단을 함께 저장 | 자동 해석을 검토하고 수정 근거를 남기기 위해 | 원문 근거·반례·분류 정정·이유 기록 |
| 근거 바로 이동 | 제안에서 원문을 검토하는 흐름을 줄이기 위해 | 제안에 연결된 댓글로 이동 |
| 실제 참가자와 시험 기록 구분 | 기능 검사 자료가 성과에 섞이지 않도록 | 시험용 제외, 중복 참여 차단, 중단자 집계 |
| 개선 사례를 문서로 생성 | 문제·기여·실행·측정을 검토 가능한 형태로 전달하기 위해 | 프로젝트 저장 이력, 역할별 피드백, Markdown·인쇄용 HTML |

변경 전 흐름: 제안 확인 → 댓글 화면 이동 → 근거 탐색 → 반례 검토 → 가설 작성.

변경 후 흐름: 제안 확인 → 근거 바로 이동 → 원문·반례 검토 → 가설 작성.

기능 정의: 같은 저장 자료를 사용하고 기존 방식에서 근거 이동 버튼을 숨겨 비교합니다. 참가자는 서로 다른 근거 댓글 2개와 별도 반례 1개를 골라 20자 이상 가설을 작성합니다. 형식 충족 여부와 실제 답변 타당성을 구분합니다.

## 효과를 확인할 방법

| 지표 | 정의 | 현재 관찰값 |
| --- | --- | --- |
| 과제 성공률 | 시작한 실제 참가자 중 10분 안에 형식을 충족하고 원문 검토에서 타당하다고 판정된 비율 | 미측정 |
| 중앙 소요 시간 | 답변을 제출하고 검토된 실제 참가자의 소요 시간 중앙값 | 미측정 |
| 근거 없는 주장 | 표본을 전체 고객으로 일반화하거나 미확인 효과를 주장한 답변 건수 | 미측정 |
| 중단 건수·이유 | 시작 뒤 과제를 끝내지 못한 참가자와 막힌 이유 | 미측정 |

동일한 수집 시점·과제·설명·기기 조건을 유지하고, 서로 다른 참가자를 기존·개선 방식에 배정합니다. 작은 표본의 탐색적 관찰이며 차이만으로 인과관계를 확정하지 않습니다. 검토자의 판단 이유와 실제 참가자의 불편을 함께 기록합니다.

## 확인된 결과와 한계

현재 확인한 결과는 도구의 기획·구현과 기술 검증입니다. 프로젝트 저장·이력·버전 충돌, 잘못된 원문 근거 연결 차단, 실제/시험 구분, 중복 참여 차단, 균형 배정, 중단자의 분모 포함, 문서 생성을 격리된 로컬 자료로 점검했습니다. 이 결과는 고객경험 개선 효과가 아닙니다.

공개 댓글만으로 상담 문의 감소, SLA 또는 CSAT 개선을 입증할 수 없습니다. 자동 분석은 규칙 기반 탐색 보조이며 다국어 원문과 반례를 사람이 검토해야 합니다. 자막·뉴스 댓글 확보에는 제약이 있습니다. 조직 협업은 실제 참여자의 요청·응답·반영 기록이 생긴 범위에서 추가하겠습니다.

## 다음 실행

실제 참가자에게 고정 과제를 수행하게 하고 관찰한 불편을 기록합니다. 답변을 원문과 대조해 판정한 뒤, 전후 성공률·시간·품질을 해석합니다. 실제 기록이 쌓이면 이 초안의 미측정 항목을 검토 가능한 결과로 갱신합니다.
