# ContextLens Sites v02 — 개선 실행과 검증·포트폴리오

## 목적과 첫 사례

공개 자료의 반응 분석을 기획·실행·검증 경험으로 축적한다. 첫 사례는 ContextLens의 근거 찾기와 가설 작성 경험 개선이다. 영상 댓글은 같은 사용성 과제의 자료이고, 앱의 불편을 입증하는 근거는 실제 참가자의 행동·피드백이다.

## 흐름

링크 분석·저장 → 같은 수집 시점 선택 → 문제·고객·통제 범위 정의 → 개선 후보와 선택 이유 → 전후 흐름과 실제 구현 → 실제 참가자 시험·지표 관찰 → 역할별 피드백·결정 기록 → 지원서용 문서 생성.

## 구현한 기능

- 개선 프로젝트: 자료별로 문제, 실제 관찰 근거, 개선 가설, 우선순위, 전후 흐름, 본인의 기여, 실제 변경·완료일·결과물 주소 저장.
- 원자료 연결: 선택한 수집 시점의 댓글만 근거·반례로 연결. 같은 댓글을 두 역할에 중복 선택할 수 없음. ContextLens 자체 개선에서는 댓글 선택만으로 실제 불편을 확인했다고 표시하지 않음.
- 측정: 비율과 수치를 구분. 기간·출처·정의·분자·분모·단위 기록. 분모 0·미측정은 계산하지 않으며 비율 차이는 %p로 표시. 실행일과 전후 기간의 관계 및 기간 겹침 점검.
- 사용자 시험: 익명 번호·사용 경험·실제/시험 구분. 인원 균형 배정(동률이면 무작위)과 수동 배정. 같은 자료에 실제 참가자 중복 등록 차단. 서버가 시간 기록. 중단 이유와 선택 과제 용이성 평가 저장.
- 효과 집계: 실제 참가자만 포함. 중단자는 성공률 분모에 남고 제출 시간 중앙값에서는 제외. 사람이 원문과 가설을 읽고 판정한 결과만 성공으로 집계. 시험용·미분류 이전 기록은 별도 표시.
- 협업: 혼자 진행/실제 피드백/실제 팀 협업 구분. 역할별 요청·응답·논의일·판단·본인의 반영 내용과 의사결정 기록. 계획 상태를 실제 협업으로 집계하지 않음.
- 제출 문서: 저장된 프로젝트·수집 시점·실제 시험 집계를 함께 사용해 Markdown과 인쇄용 HTML 생성. HTML을 열어 사용자가 PDF로 저장. 미기록·미측정을 유지하고 개인 프로젝트 여부·한계·기여를 표시.
- 기록 보존: 기존 cases·snapshots 유지. 별도 cx_projects와 변경 이력 테이블 사용. 저장 버전 충돌 시 덮어쓰지 않고 오류 표시.

## 화면과 접근

기존 분석 화면에서 ‘개선 프로젝트’로 이동. 새 화면은 문제·근거/실행/효과/협업/문서의 5개 단계로 구성하며 세부 근거는 펼쳐 확인한다. 모바일에서 진행 체크는 접혀 시작한다. /contextlens와 /projects 경로를 지원한다.

기존 Sites 프로젝트·접근 권한·데이터베이스를 이어 사용한다. 소유자만 접속 가능하므로, 참가자는 대면·화면 공유로 소유자의 화면에서 직접 과제를 수행한다. 실제 외부 접근 권한은 요청 없이 확대하지 않는다.

## 수용 기준

1. 저장·새로고침 후 프로젝트와 연결 수집 시점 복구. 변경 이력을 남기고 오래된 버전의 저장을 거부한다.
2. 다른 자료의 댓글·존재하지 않는 댓글을 근거로 저장할 수 없다.
3. 실제/시험/중단 기록을 만들어 실제 집계의 분모·분자가 맞는지 격리 저장소에서 확인한다.
4. 참가자의 중복 등록을 차단하며, 같은 수집 시점의 기존·개선 결과만 프로젝트 문서에 표시한다.
5. 분모 0, 분자 초과, 기간 겹침, 실제 협업이 없는 계획의 처리를 확인한다.
6. 실제 고객 성과가 없는 문서는 작성 중으로 남는다. 기술 검사·합성 자료 실행을 고객경험 개선 성과로 쓰지 않는다.

## 범위와 한계

공개 댓글은 실제 상담 문의 데이터가 아니며 문의 감소·SLA·CSAT를 직접 입증할 수 없다. 자동 분석은 규칙 기반 탐색 보조이고 사람이 원문과 맥락을 검토해야 한다. 자막과 뉴스 댓글의 자동 수집은 사이트 응답에 따라 제한된다. 각 방식 5명은 탐색적 관찰의 시작 기준이며 통계적·인과적 효과를 보장하지 않는다. 조직과의 협업·실제 성과는 사람이 참여하고 기록한 범위에서만 설명한다.
