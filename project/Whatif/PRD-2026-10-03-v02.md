# Whatif · 브런치 콘텐츠 기획서

- 작성일: 2026-10-03
- 상태: 사용자 역할 분담 반영 / 첫 소재 선택 전
- 개정: v02 — 가정별 결과 추정과 교훈 작성은 사용자가 담당. 이전 PRD.md 보존.
- 시작 계획: 이번 주말(2026-10-03~04)부터 사용자가 요청할 때 한 편씩 제작
- 저장 위치: `project/Whatif/`

## 1. 무엇을 만드는가

> 만약 그때 다른 선택을 했다면? 역사와 대중문화, 스포츠의 갈림길을 데이터로 되짚습니다.

‘만약 ~라면’이라는 질문에서 출발해 문제를 정의하고, 자료와 지표를 분석하며, 가정에 따라 결과가 얼마나 달라질 수 있는지 설명하는 브런치 연재입니다. 필요한 경우 그래프나 대시보드(여러 지표를 한눈에 보는 화면)를 함께 만듭니다.

독자가 흥미로운 사건을 다른 관점에서 이해하도록 돕고, 제작자의 기획력·분석력·설명 능력이 드러나는 결과물을 쌓습니다. 독자 재미와 분석 포트폴리오 중 어느 쪽에 더 무게를 둘지는 아직 정하지 않았습니다.

## 2. 해결하려는 문제와 독자

- 문제: ‘그때 다른 선택을 했다면’이라는 이야기는 흥미롭지만, 사실과 추측이 섞이면 무엇을 믿을 수 있는지 알기 어렵습니다.
- 제공할 가치: 실제 기록, 비교 기준, 가정, 알 수 없는 부분을 구분해 독자가 분석 과정을 따라갈 수 있게 합니다.
- 예상 독자: 역사·대중문화·스포츠의 갈림길에 관심이 있고, 숫자를 어렵지 않게 읽고 싶은 사람입니다. 구체적인 독자층은 첫 글 제작 시 좁힙니다.

## 3. 핵심 분석 구조

**질문 → 사실 확인 → 문제 정의 → 지표 분석 → 가정별 결과 추정 → 시각화 → 해석과 한계**

실제로 일어나지 않은 상황을 가정해 비교하는 ‘반사실 분석’을 사용합니다. 가상 결과는 관측된 성과가 아니라 추정치입니다.

| 구분 | 다루는 내용 | 표현 원칙 |
|---|---|---|
| 실제 관측 | 기록과 자료로 확인한 변화 | 출처·기간·대상·단위를 표시 |
| 가상 결과 | 다른 선택을 했을 때의 가능성 | 가정·계산 방식·결과 범위·불확실성을 표시 |
| 콘텐츠 성과 | 발행한 글에 대한 실제 반응 | 확보 가능한 자료만 사용하고 같은 관찰 기간으로 비교 |

## 4. 소재 후보

아래는 사용자가 제안한 후보입니다. 사건의 구체적 경위, 프로그램 명칭, 발생 시점과 자료 확보 가능성은 제작 전에 검증합니다. 표의 지표는 후보이며 확보된 데이터가 아닙니다.

| 소재 | 질문을 좁히는 방향 | 근거·지표 후보 | 시각화 후보 |
|---|---|---|---|
| 김재규가 박정희 대통령 암살 이후 육군본부가 아닌 중앙정보부로 갔다면 | 이동 경로가 당시 신병 확보와 지휘권 확보에 어떤 차이를 만들 수 있었을까 | 사건 시간표, 지휘 체계, 인물별 행동과 사료 | 시간표, 선택의 갈림길 그림 |
| 리센느 원이가 사용자가 언급한 ‘나의 연수 아저씨’ 프로그램에 출연하지 않았다면 | 출연 이후 관심 변화 중 프로그램과 관련된 부분은 얼마나 될까 | 검색 관심도, 관련 영상 반응, 다른 활동 일정, 비교 대상 변화 | 시점별 변화 그래프, 비교 차트 |
| 삼성 라이온즈 구자욱이 2루까지 주루하지 않아 다치지 않았더라면 | 정상 출전했다는 가정에서 팀의 득점 기대는 얼마나 달라질까 | 출전 경기, 타격 기록, 대체 선수 기록, 상대 투수와 경기 상황 | 실제와 가정 비교, 조건별 결과 범위 |

첫 소재와 제작 순서는 사용자가 선택합니다. 주루 여부와 부상 사이의 관계도 확인 전에는 사실로 단정하지 않습니다.

## 5. 한 편을 만드는 순서

1. **소재와 질문 정하기:** 사용자가 소재를 요청하면 답할 질문 하나, 비교 기간, 다룰 결과를 정합니다.
2. **자료 확인하기:** 출처와 자료의 범위를 확인합니다. 자료가 부족하면 질문을 좁히거나 정성 분석으로 전환합니다.
3. **지표 정하기:** 핵심 지표 2~3개를 우선 선정하고 의미, 단위, 계산 방법, 비교 대상을 적습니다.
4. **실제 자료 분석하기 — Codex:** 실제 변화와 비교 지표를 정리하고 다른 원인과 반례를 확인합니다.
5. **가정별 결과 추정하기 — 사용자:** 사용자가 바꿀 조건, 예상 결과, 근거와 불확실성을 작성합니다. Codex는 임의의 가정·확률·예측값을 채우지 않습니다.
6. **시각화하기 — Codex / 교훈 작성하기 — 사용자:** 확인된 실제값과 사용자가 제공한 추정값을 구분해 그래프나 대시보드로 만듭니다. 교훈과 최종 해석은 사용자가 작성합니다. 원고 편집은 요청 시 사용자 내용을 보존해 돕습니다.
7. **검토하기:** 사용자가 원고와 해석을 확인합니다. 외부 발행은 별도 요청이 있을 때 진행합니다.
8. **발행 후 돌아보기:** 실제 확보한 반응을 살펴보고 다음 글의 개선점을 정합니다.

자동 제작이나 예약 발행은 설정하지 않습니다. 사용자의 요청이 들어오면 해당 편을 시작하며, 여러 편을 임의로 한꺼번에 만들지 않습니다.

## 6. 브런치 원고 기본 구성

1. **만약 그 순간…**: 독자가 궁금해할 장면과 질문
2. **정확히 무엇이 달라졌을까?**: 분석 범위와 비교 기준
3. **실제로 확인되는 것은…**: 사실, 자료, 핵심 지표
4. **조건을 바꿔보면…**: 가정별 결과와 시각화
5. **그래서 지금 무엇을 배울까?**: 해석, 한계, 독자에게 남길 질문
6. **출처와 분석 메모**: 자료 링크, 기준 시점, 계산과 가정

글 길이와 문체는 첫 편을 보고 조정합니다. 숫자로 표현하기 어려운 역사적 판단을 억지로 점수화하지 않습니다.

## 7. 시각화와 대시보드 기준

- 첫 편은 핵심 그래프 한두 개를 우선 고려합니다.
- 실제값과 추정값을 제목·범례·주석으로 명확히 구분합니다.
- 그래프에 기간, 단위, 출처, 주요 가정을 표시합니다.
- 독자가 조건을 바꾸며 결과를 살펴볼 필요가 있을 때 대시보드를 만듭니다.
- 대시보드가 없어도 글만으로 핵심 결론과 한계를 이해할 수 있어야 합니다.
- 브런치 내 표시 방식과 외부 링크 활용 가능성은 실제 제작 시 확인합니다. 삽입 기능을 지원한다고 미리 가정하지 않습니다.

## 8. 발행 콘텐츠의 성과 측정

| 확인할 것 | 측정 후보 | 적용 조건 |
|---|---|---|
| 독자에게 도달했는가 | 글 조회 수 | 플랫폼에서 확인 가능한 경우 |
| 다음 글도 읽고 싶게 했는가 | 구독자 수 변화 | 글 한 편의 효과로 단정하지 않고 다른 발행 활동도 기록 |
| 생각과 토론을 만들었는가 | 주제 관련 댓글, 근거 질문, 반론 | 단순 반응 수와 내용의 깊이를 구분 |
| 시각화가 활용되었는가 | 대시보드 방문·조건 변경 | 별도 측정이 가능한 경우에만 적용 |

발행 후 7일을 첫 비교 시점으로 제안합니다. 목표 수치는 아직 확정하지 않으며, 초기 글의 실제 결과를 보고 정합니다. 제공되지 않는 독서 완료율이나 구독 전환율을 추정해 실제 성과처럼 기록하지 않습니다.

## 9. 품질 기준과 완료 조건

- 질문이 하나로 좁혀져 있고 비교 기간과 대상이 명확합니다.
- 주요 사실에 출처가 있으며 서로 충돌하는 기록은 그 차이를 설명합니다.
- 사실, 가정, 해석, 알 수 없는 부분이 구분됩니다.
- ‘이후에 일어났다’를 ‘그것 때문에 일어났다’로 바꾸어 단정하지 않습니다.
- 계산 결과는 원자료와 계산 방식으로 다시 확인할 수 있습니다.
- 추정 결과는 가정이 달라지면 어떻게 변하는지 설명합니다.
- 시각화의 값과 본문이 일치하고, 독자가 읽을 수 있는지 확인합니다.
- 사용자가 확인하기 전에는 원고를 발행 완료로 기록하지 않습니다.

## 10. 결과물 보관과 역할

- 최신 기획서: `project/Whatif/PRD-2026-10-03-v02.md`
- 초기 기획서 보관: `project/Whatif/PRD.md`
- 각 편의 결과물: `project/Whatif/주제-YYYY-MM-DD-v01/` 아래에 원고, 출처·분석 자료, 필요한 시각화를 함께 보관합니다.
- 수정 결과는 새 버전으로 저장합니다. 기존 파일을 덮어써야 할 때는 사용자 요청을 확인합니다.
- 진행 기록은 TOBEA 최상위 `작업일지.md`에만 덧붙입니다.
- 사용자: 소재와 질문 선택, 가정별 결과 추정, 지금 얻을 교훈 작성, 원고 확인과 발행 여부 결정
- Codex: 만약 질문 제안, 실제 사실 확인과 구조화, 비교 지표 설계, 요청된 관측값 계산, 사용자 제공 결과의 시각화, 근거와 한계 정리. 가정별 결과와 교훈은 대신 작성하지 않습니다.

## 11. 다음 요청에서 시작할 일

사용자가 첫 소재를 알려주면 질문과 자료 범위를 정하는 단계부터 시작합니다.

예: “Whatif 첫 편은 구자욱으로 시작하자.”

현재 미정: 첫 소재, 독자 재미와 포트폴리오의 우선순위, 첫 글 분량, 발행 주기. 이번 문서 작성에는 개별 사건 조사, 실제 데이터 분석, 원고 제작, 대시보드 구현, 외부 발행이 포함되지 않았습니다.


## 12. 요청별 스킬 사용

| 요청 | 사용할 스킬 | 결과 |
|---|---|---|
| 만약 질문 제안 | `$whatif-questions` | 흥미로운 질문 후보, 확인된 전제, 자료 가능성 |
| 실제 사실 확인 | `$whatif-fact-check` | 근거와 판정이 있는 사실표, 필요한 시간표, 미확인 사항 |
| 비교 지표 설정 | `$whatif-metrics` | 지표 정의, 계산식, 기간과 비교 대상, 출처와 한계 |
| 대시보드 시각화 | 기존 `data-analytics:build-dashboard` | 실제 자료와 사용자 추정 결과를 구분한 화면 |

새 스킬은 TOBEA의 `.agents/skills/`에 저장합니다. 해당 단계를 요청할 때 사용하며 자동으로 다음 단계를 연쇄 실행하지 않습니다.

가정별 결과와 교훈을 만드는 스킬은 만들지 않습니다. 시각화 시 사용자 값이나 계산 규칙이 없으면 해당 영역을 미입력으로 남깁니다. 사용자가 정한 규칙의 기계적 계산이 필요하면 명시된 규칙만 구현하고 새로운 추정 모델을 선택하지 않습니다. 결과가 관측인지 사용자 추정인지 화면에서 구분합니다.

예시 요청:
- “$whatif-questions 야구 소재로 만약 질문 3개 제안해줘.”
- “$whatif-fact-check 선택한 질문의 실제 사건을 확인해줘.”
- “$whatif-metrics 확인된 사실을 바탕으로 비교 지표를 정해줘.”
- “내가 작성한 가정별 결과를 기존 대시보드 스킬로 시각화해줘. 가정과 교훈은 추가하지 마.”
