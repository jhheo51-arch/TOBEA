# Whatif 콘텐츠 기획서

작성일 2026-10-03 · 최신 개정 v03 · 이전 PRD.md와 v02 보존

## 목적과 범위

Whatif는 **기획 → 분석 → PM적 사고 → 결과 도출**을 보여주는 브런치 콘텐츠입니다. PM적 사고는 목표와 선택지를 정하고, 근거·위험·제약을 비교해 판단하는 사고입니다. 사용자가 질문과 해석의 주인이 되고 AI는 근거를 준비하고 논리를 검토합니다.

서비스나 별도 앱 구현은 현재 범위에 포함하지 않습니다. 리서치·검증 에이전트 하나로 시작하며 지표 분석과 그래프 제작은 기존 스킬을 사용합니다. 여기서 에이전트는 현재 대화에서 정해진 임무와 절차를 수행하는 AI 역할입니다. 별도 서버나 상시 자동 실행 프로그램을 뜻하지 않습니다.

## 확정 제작 흐름

**사용자가 직접 문제 정의 → AI 사실 검증 → AI 지표 분석 → 사용자 가정·해석 작성 → AI 반론 검토 → 필요한 그래프 제작 → 사용자 최종 글 완성**

‘질문 검토’는 사용자가 정의한 문제를 받은 직후, 본격적인 사실 검증 전에 수행합니다. AI가 문제를 대신 결정하거나 조용히 바꾸지 않습니다. 범위 변경이 필요하면 변경 이유와 좁힌 질문을 제안하고 사용자 선택을 받습니다. 원래 범위에서 가능한 조사까지 멈출 필요는 없습니다.

| 단계 | 담당 | 산출물과 다음 단계 조건 |
|---|---|---|
| 문제 정의와 질문 검토 | 사용자 정의, AI 검토 | 질문 원문·바꿀 조건·비교 대상·기간·답변 가능 범위. 진행 가능/조건부 가능/재정의 필요 판정 |
| 사실 검증 | 리서치·검증 에이전트 | 실제 사건 시간표, 핵심 주장별 근거 카드, 확보 자료와 공백 |
| 지표 분석 | 기존 whatif-metrics 스킬 | 정의·계산식·기간·비교 기준·자료 상태·계산 결과. 핵심 수치도 카드와 연결 |
| 가정과 해석 | 사용자 | 바꿀 조건·유지할 조건·예상 결과·근거·불확실성·해석 |
| 반론 검토 | 같은 리서치·검증 에이전트 | 사용자 주장별 반대 근거·대안 설명·비교 오류·판단 변경 조건·보완 제안 |
| 필요한 그래프 | 기존 시각화 스킬 | 본문 질문에 필요한 그림만 제작. 실제값과 사용자 추정값 구분 |
| 최종 글과 교훈 | 사용자 | 사용자가 최종 해석·교훈·발행 여부 결정. AI 편집은 요청 시 지원 |

사용자 가정·해석이 없으면 반론 검토를 완료 처리하지 않습니다. 검토 기준과 입력 양식까지만 준비합니다. 근거가 없는 주장을 반박된 사실로 표시하지 않습니다.

## 에이전트 하나의 임무

> Whatif 질문을 받으면 실제 사건을 복원하고, 주장별 근거와 분석 가능한 데이터를 검증해 사용자에게 넘기는 리서치 에이전트.

임무 원본은 [agent mission.md](<agent mission.md>)에서 관리합니다. 실행 진입점은 `$whatif-research`입니다. 별도의 지표 분석 에이전트와 시각화 에이전트는 만들지 않습니다. 반론 검토도 같은 역할이 수행하며 독립된 외부 검증을 받았다고 표현하지 않습니다.

## 고도화 방법 1 질문 검토

확인할 항목은 사용자의 질문 원문, 실제 사건, 바꿀 선택 하나, 비교 결과, 기간, 당시 알 수 있던 정보, 필요한 자료와 확보 가능성입니다. 질문의 흥미와 답변 가능성을 구분합니다. 인과관계를 밝히는 데 필요한 자료가 없으면 기술적 비교까지만 진행합니다. 분석 질문 제안은 사용자의 최종 문제 정의와 구분합니다.

## 고도화 방법 2 근거 카드

사건 전제, 중요한 수치, 인과 주장, 최종 결론을 지지하는 문장을 핵심 주장으로 봅니다. 한 카드에는 하나의 판단 단위를 담고 문서 안에서 카드 번호로 연결합니다.

카드 필수 항목: **번호 / 주장 / 종류(사실·계산·해석·가정) / 출처와 작성·조회일 / 확인 범위 / 반대 근거·대안 설명 / 아직 모르는 것 / 판정 / 사용할 수 있는 표현**.

판정: 확인됨, 일부 확인, 자료 충돌, 확인 불가, 반박 근거 있음, 가정으로만 사용. 수치에는 분모·기간·단위·계산식과 원자료 경로를 포함합니다. 반복 전재 기사를 독립 근거로 세지 않습니다. 원문을 못 읽었거나 이전 확인 자료를 재사용하면 그 상태를 밝힙니다.

## 고도화 방법 3 반론 검토

사용자가 가정과 해석을 작성하면 원문을 보존하고 주장별로 검토합니다. 확인 항목은 사후 판단 오류, 다른 원인, 비교 대상·기간의 공정성, 표본 크기, 중복 계산, 가정에서 결론까지의 논리, 판단을 바꿀 근거입니다.

결과는 ‘사용자 주장 → 연결 카드 → 가장 강한 반론 → 근거 수준 → 보완 제안 → 남은 판단’ 형식입니다. 근거가 충분한 주장은 유지 가능으로 표시합니다. 반론 개수를 맞추려고 반대 사실을 만들지 않습니다. 검토 통과가 사실 전체의 증명이나 예측의 적중을 뜻하지 않습니다. 최종 수정과 교훈은 사용자가 결정합니다.

## 스킬과 시각화

| 용도 | 활용 |
|---|---|
| 질문 검토·사실 검증·해석 후 반론 검토 | 새 진입점 whatif-research, 기존 whatif-fact-check 활용 |
| 비교 지표 설정과 요청된 계산 | 기존 whatif-metrics |
| 질문 아이디어 지원 | whatif-questions, 사용자가 요청한 경우만 사용 |
| 글에 넣을 그래프 | 기존 data-analytics:visualize-data |
| 대시보드 | 별도 요청이 있을 때 기존 build-dashboard 사용. 기본 산출물 아님 |

## 글의 구성과 성과

장면과 사용자 질문 → 확인된 사실 → 지표 비교 → 사용자 가정·해석 → 필요한 그림 → 사용자 교훈과 출처 순으로 편집합니다. 반론 검토 결과는 관련 문장과 한계 설명에 반영합니다.

발행 후에는 확보 가능한 조회·구독 변화·내용 있는 댓글 등을 동일한 관찰 기간으로 비교합니다. 플랫폼에서 제공하지 않는 지표를 만들어내지 않습니다. 목표 수치와 발행 주기는 아직 미정입니다.

## 저장과 완료 기준

콘텐츠마다 `project/Whatif/주제-날짜-v01/` 전용 폴더를 사용합니다. 같은 편의 보완 자료는 해당 폴더에 새 이름으로 저장합니다. 공통 PRD와 agent mission.md는 Whatif 대표 폴더에 둡니다. 진행 기록은 최상위 작업일지 하나에만 남깁니다.

완료 기준은 사용자 질문 보존, 모든 핵심 주장과 카드 연결, 계산 재현 가능성, 공백 표시, 사용자 해석 수신 후 반론 검토, 필요한 시각화 검증, 사용자 최종 글 확인입니다. 각 단계 완료와 전체 콘텐츠 완료를 구별합니다.

## 구자욱 편 적용 상태

첫 소재는 ‘만약 그 순간 구자욱이 2루로 뛰지 않았더라면’입니다. 기존 분석을 보존하고 같은 폴더에 질문 검토·근거 카드·반론 검토 양식을 추가했습니다. 기존 확인 자료를 구조화한 것이며 이번 개정에서 새 웹 조사까지 완료했다고 보지 않습니다.

질문 검토와 근거 카드 작성은 완료했습니다. 사용자 가정·해석이 아직 없어 실제 반론 검토는 입력 대기입니다. 관련 문서는 [검토 패키지](gu-jawook-2026-10-03-v01/review-package-2026-10-03-v01.md)입니다.
