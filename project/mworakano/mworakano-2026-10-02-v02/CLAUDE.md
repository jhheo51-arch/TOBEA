# 뭐라카노 개발 인계

먼저 `PRD.md`, `README.md`, `prompts/scoring.md`, `skills/english-question-generator/SKILL.md`를 읽는다. 사용자와 한국어 존댓말로 대화한다. 사용자는 비개발자다. 전문 용어는 풀어 설명하고 사용자가 코드를 수정하도록 요구하지 않는다.

## 고정 결정

- 이름 뭐라카노, 목표 OPIc 향상, 현재 공급자 Gemini.
- 토익스피킹 구조를 응용한 학습 점수만 사용. 일반 0~3, 의견 0~5. 공식 0~200 및 OPIc 등급 환산 금지.
- 평가에는 실제 음성이 필요하다. A/B 독립 2회, 차이 시 C 1회. 불확실하거나 근거 형식이 깨지면 보류/오류. 평균내지 않는다.
- ILR 중심·8개 영역 0~4 합산은 이전 설계이며 복원하지 않는다.
- 기존 결과물과 개인 `.env`를 보존한다. 키를 출력·공유·브라우저 저장하지 않는다. 공개 배포는 별도 사용자 요청 없이는 하지 않는다.

## 실행과 구조

Node.js 24+, 의존 패키지 없음. `npm start` / `npm test`. `server.mjs`는 127.0.0.1:8794, `public/`는 화면, `public/core.js`는 핵심 검사, `tests/`는 내장 node:test 검사. 서버 코드 변경 후 서버 재시작, 정적 파일 변경 후 화면 새로고침.

설정 순서: 환경변수 > 버전 폴더 `.env` > 부모 프로젝트 `.env`. UI 연결은 서버 메모리에만 설정한다. 빈 키 상태에서 가짜 점수나 임의 채점 결과를 제품에 표시하지 않는다. 테스트용 AI 응답은 테스트에 주입하며 제품 화면에 연결하지 않는다.

## 현재 미검증·미완료

실제 Gemini 요청과 채점 품질 미검증. 브라우저 도구가 로컬 주소 접근을 차단하여 시각 검증과 녹음 동작 미검증. 국내 OPIc 최신 설문과 전체 선택지 동일성 미확인. 최신 뉴스 안정 수집과 기사 전문 표시 미구현. 근거 시간의 실제 정확성·음성 길이의 서버 독립 측정·백업 복원은 후속 과제다.

다음에는 사용자 브라우저에서 설문→녹음→직접 기록을 확인하고 키 연결 후 실제 발화 1건을 채점한다. 그다음 반복 평가와 전문가 대조로 신뢰도를 검증한다. 숫자 출력 성공과 채점 품질 검증을 구분한다.

TOBEA 안에서 작업한다면 최상위 AGENTS.md가 우선하며 최상위 `작업일지.md`에만 진행 기록을 덧붙인다. 별도 작업일지나 todo 파일을 만들지 않는다. 이 폴더를 다른 환경으로 옮긴 경우에도 사용자 자료를 임의로 외부에 전송하지 않는다.
