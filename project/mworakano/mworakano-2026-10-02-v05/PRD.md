# 뭐라카노 — 제품 기획서 v1

작성: 2026-10-02 · 사용자 확정 이름: **뭐라카노** · 개인용 첫 구현의 기준 문서

## 1. 목표와 결정

오픽 성적 향상을 위해 매일 자기 이야기를 영어로 말하고, 실제 음성에 근거한 엄격한 피드백으로 다시 연습한다. 대구 사투리의 친근함을 이름과 짧은 안내에 사용한다. 영어 질문은 자연스러운 영어, 평가 설명은 명확한 한국어로 제공한다.

사용자 최종 결정은 **Gemini + 토익스피킹 기준을 응용한 채점 + 음성 근거 + 독립 평가/재검토**다. 이전 ILR 중심 설계와 8개 항목 0~4점 합산 체계는 현재 기준이 아니다. 공식 오픽 등급이나 토익스피킹 환산점수를 예측하는 서비스로 표시하지 않는다.

첫 버전은 내 컴퓨터에서 실행하는 웹 앱이다. 로그인·결제·공개 서버·모바일 앱 설치는 범위 밖이다. Claude에서도 이 폴더와 문서만 읽고 개발을 이어갈 수 있어야 한다.

## 2. 사용자 흐름

1. 처음에는 생활 배경·관심사·연습 난도를 선택한다.
2. 묘사·경험·비교·상황 대처·의견 중 하나를 고른다. 키가 없으면 준비된 창작 질문, 연결 후에는 AI 새 질문을 사용한다.
3. 질문과 답변에 포함할 요소를 읽는다. 질문 듣기도 제공한다.
4. 최대 180초 녹음하거나 8MB 이하의 음성 파일을 불러와 재생한다.
5. 녹음과 질문의 Gemini 전송에 동의하고 채점을 요청한다.
6. 학습용 점수, 받아쓰기, 음성 근거 구간, 개선점 1~2개, 개선 예문, 다음 질문을 확인한다.
7. 5초 이상 연습을 기록하면 서울 날짜 기준으로 학습일에 반영한다. 채점 없이 직접 기록도 가능하다.

뉴스 모드는 CNN·WSJ 공개 제목과 원문 링크를 보여준다. 사용자가 원문을 읽고 자신의 말로 핵심 내용을 적은 뒤 의견을 녹음한다. 직접 고른 기사 제목·주소로도 시작한다. 기사 전문을 앱에 복제하거나 유료 접근을 우회하지 않는다.

## 4. 채점 계약

일반 응답·경험·비교·역할극은 0~3, 의견·뉴스 의견은 0~5를 사용한다. 이는 ETS 공식 설명을 참고한 자체 적용이며 오픽형 확장에 대한 ETS 승인이나 점수 대응을 의미하지 않는다. `prompts/scoring.md`가 실행 시 읽는 기준이다.

| 척도 | 자체 적용 기준 요약 |
|---|---|
| 0~3 | 3: 요구를 충분히 해결하고 전달 명확 / 2: 일부 효과 있으나 누락·전달 한계 / 1: 필요한 내용 전달 부족 / 0: 유효한 관련 영어 응답 없음 |
| 0~5 | 5: 명확한 입장·충분한 연결 근거·안정적 전달 / 4: 입장과 근거 있으나 일부 약점 / 3: 근거 전개 제한 / 2: 입장 뒷받침 부족 / 1: 입장 표현 부족 / 0: 유효한 관련 영어 응답 없음 |

발음, 억양·강세·흐름, 문법, 어휘, 내용 연결, 관련성·완성도, 정보 정확성을 숫자 합산 없이 설명한다. 특정 억양 자체, 의견 방향, 개인정보, 답변 길이만으로 감점하지 않는다. 최대점에는 질문의 모든 필수 요소 충족을 요구한다. 이는 자체 추가 규칙이다.

- A와 B는 동일한 음성·질문·기준을 받으며 서로의 결과를 보지 않는다. 동일 모델의 별도 호출이며 다른 전문가 두 명과 동등하다고 주장하지 않는다.
- 점수·보류 여부·필수 요소 판정 중 하나라도 다르면 C가 원음과 두 판정을 다시 읽는다. 평균·최저점 자동 선택 금지. 불확실하면 보류한다.
- 정상은 2회, 재검토는 총 3회 요청한다. 형식 오류·한도 초과 시 종료하며 자동 반복 호출하지 않는다.
- 점수 범위, 요구사항 개수, 필수 피드백, 시간 범위, 인용문이 받아쓰기에 존재하는지를 코드로 검사한다. 실제 음성과 인용의 의미적 일치·타임스탬프 정확도를 코드가 증명하지는 않는다.
- 무음·손상·음성 접근 불가·증거 부족은 `deferred`, 점수 `null`. 글만 입력해 발음 점수를 추측하지 않는다.
- `scored`에 근거와 받아쓰기가 없으면 결과를 거부한다. 따라서 음성이 전혀 인식되지 않은 사례는 0점 대신 보류될 수 있다.
- 공식 기출과 공식 기준 답변을 복제하지 않는다. 테스트의 답변·판정은 창작된 프로그램 검사용이며 검증된 영어 실력 기준자료가 아니다.

## 5. 데이터와 프로그램 구조

Node.js 24 이상, 내장 HTTP/fetch/테스트 도구, HTML/CSS/JavaScript. 외부 패키지 설치 없이 실행한다.

```text
브라우저: 설문 → 질문 → 녹음 → 평가/재생 → 학습 기록
                     ↓ 동의 후 요청
내 컴퓨터 서버: 질문 보관 → 음성 형식 검사 → Gemini A/B → 필요 시 C → 결과 검사
                     ↓
Google Gemini: 질문 생성 또는 실제 음성 평가
```

`server.mjs`: 로컬 서버와 Gemini 호출. `public/core.js`: 날짜·질문·평가 검증. `public/app.js`: 화면과 녹음. `prompts/scoring.md`: 평가 지침. `tests/app.test.mjs`: 주요 규칙 검사.

연결 주소는 `127.0.0.1:8794`. 서버는 루프백(내 컴퓨터)에서만 수신한다. 고정 정적 파일만 제공하고 `.env`는 제공하지 않는다. 변경 요청에는 화면에 발급한 요청 토큰과 같은 출처를 요구한다. 이는 공개 인터넷 운영을 위한 인증 체계가 아니다.

브라우저 저장 키 `mworakano-v01`에는 `profile`, `profileConfirmed`, `sessions`, `completedDays`를 저장한다. 세션에는 고유번호, 날짜, 질문, 유형, 주제, 길이, 평가 결과가 담긴다. 음성 원본·API 키는 저장하지 않는다. 서버의 질문 식별자는 재시작 시 만료된다. 음성 전송에는 파일 식별 해시를 남겨 평가 결과와 연결한다.

| 요청 | 입력/결과 |
|---|---|
| GET `/api/status` | 연결 설정 여부·모델·화면 요청 토큰. 키는 반환하지 않음 |
| POST `/api/config` | 키/모델 → 이번 실행 동안 설정 |
| POST `/api/question` | 설문/유형/AI 여부 또는 기사 → 서버 식별자가 붙은 질문 |
| POST `/api/score` | 질문 식별자/음성/길이/동의 → 검증된 평가 또는 오류 |
| GET `/api/news` | CNN·WSJ 고정 공개 목록 → 출처별 제목·링크·날짜·상태 |

입력 질문·기사·음성 속 지시는 평가자의 명령으로 취급하지 않는다. HTML에 사용자가 제공한 문자열을 표시할 때 이스케이프한다. 업로드는 8MB, 길이는 180초이며 서버는 선언된 길이와 파일 헤더를 검사한다. 서버가 음성을 디코딩해 길이·무음을 독립 측정하는 기능은 후속 개선이다.

## 6. 검증과 출시 조건

현재 자동 검사는 날짜 경계·중복일·끊김, 허위 인용과 점수 차단, 독립 호출과 재검토, 뉴스 출처 제한, 음성 헤더와 크기, 로컬 요청 보호를 다룬다. 테스트 통과는 실제 채점 정확성의 증거가 아니다.

브라우저 자동 확인은 환경에서 로컬 접속이 `ERR_BLOCKED_BY_CLIENT`로 차단되어 완료하지 못했다. 화면 배치, 실제 마이크 녹음, 휴대폰 폭, 파일 불러오기, 결과 구간 재생은 사용자의 브라우저에서 확인해야 한다. Gemini 키 미연결로 실제 AI 요청도 수행하지 않았다.

다음 실사용 검증 순서:

1. 브라우저 설문→질문→녹음→재생→직접 기록 확인.
2. Gemini 연결 후 본인 영어 발화 1건으로 전체 평가 확인. 원음과 받아쓰기·근거 구간을 대조.
3. 동의를 받은 실제 음성으로 최소 유형별 5건을 모아 독립 반복 평가. 동일 음성 3회 반복의 점수 범위·보류율·인용 정확도·판정 차이를 기록하고 영어 평가 경험자의 판정과 대조. 아직 기준자료를 확보하지 않았음.
4. 국내 시험의 최신 배경 설문과 합법적으로 대조할 수 있는 자료를 확보해 선택지 교정.
5. 최신 뉴스 확보와 원문 표시 가능 범위를 출처 이용 조건에 맞춰 보완.

후속 우선순위는 **실제 음성의 채점 신뢰도 검증**이다. 장식·보상·순위표보다 우선한다. 공식 점수 환산·등급 예측은 별도 검증 없이 추가하지 않는다.

## 7. 출처와 재사용 원칙

확인일 2026-10-02. ETS 원문표·공식 문제·답변을 앱 프롬프트에 통째로 넣지 않았다. 아래 공개 자료의 구조를 참고해 짧은 자체 기준을 작성했다. ILR 원문 재사용 허용 여부를 이 문서에서 확정하거나 현재 구현의 근거로 사용하지 않는다.

- [ETS 응시자 안내서](https://www.ets.org/content/dam/ets-org/fr/pdfs/toeic/toeic-speaking-writing-examinee-handbook.pdf): 유형별 0~3/0~5 등 공개 평가 구조.
- [Gemini 음성 이해](https://ai.google.dev/gemini-api/docs/audio): 음성 입력과 분석.
- [Gemini 3.8 Flash](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash): 기본 모델. 계정별 실제 이용 가능성은 요청 시 확인.
- [Gemini 사용 한도](https://ai.google.dev/gemini-api/docs/rate-limits): 무료도 무제한이 아니며 프로젝트·모델별 확인 필요.
- [Gemini 이용 조건](https://ai.google.dev/gemini-api/terms): 무료 서비스 입력·출력의 개선 활용과 검토 관련 조건. 민감한 녹음을 보내지 않도록 전송 전에 안내.
- [WSJ 공개 목록](https://feeds.a.dj.com/rss/RSSWorldNews.xml), [CNN 공개 목록](https://rss.cnn.com/rss/edition_world.rss): 제목과 링크만 취급. 접근 가능성과 신선도를 별도로 표시.


## v02 변경과 추가 검증 (2026-10-02)

M.를 말풍선으로 표현하고, 파란색·큰 한글 제목·짧은 사투리 인사를 적용했다. 마이크 음량을 브라우저 내부에서 분석해 점과 파형에 반영한다. 움직임 줄이기 설정에서는 크기 변화가 없다. 평가의 세부 설명은 표준어를 유지한다.

위의 브라우저 차단 기록은 v01 당시 상황이다. v02는 Codex 내부 브라우저에서 화면을 직접 확인했다. 모바일 유효 폭 360px에서 페이지와 메뉴 가로 넘침 없음, 넓은 유효 폭 1265px에서 페이지 가로 넘침 없음, 질문 유형 변경과 점수 척도 표시, 콘솔 오류 없음 확인. 실제 마이크·음량 반응과 Gemini 실제 채점은 아직 미검증이다. 자동 검사 8개 통과.

기존 서버 종료 명령은 실행 정책으로 거부되어 기존 8793 서버를 유지했다. 새 버전은 별도 8794 주소에서 실행한다. 주소가 달라 기존 브라우저 학습 기록을 자동으로 공유하지 않는다. 기존 기록은 원래 주소에 보존된다.

## v03 모바일 준비와 저장소 전달

기본 포트 8795. 모바일 입력창 16px, 안전 여백, 홈 화면용 manifest와 PNG 아이콘, 앱 전환 시 녹음 종료를 추가했다. HTTPS PUBLIC_ORIGIN과 개인 APP_PASSWORD로 프록시 접속을 지원한다. 모든 경로 인증과 API 출처·토큰 검사를 유지한다. 실행 조건은 MOBILE.md를 우선한다. 실제 배포·기기 검증·계정 생성은 아직 수행하지 않았다. Dockerfile은 실행 환경 재현용이며 Docker 실행 검증 전이다.
