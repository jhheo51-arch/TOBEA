# 제품 개선 실험실의 AI 에이전트 설계

## 어떤 유형인가
정해진 절차로 일하는 기획 보조 에이전트입니다. 사용자의 목표와 집계 자료를 읽고 개선 가설을 제안한 뒤 검토합니다. 스스로 도구를 선택하거나 웹을 돌아다니는 자율 에이전트는 아닙니다. 한 모델을 두 번 호출해 제안 역할과 검토 역할을 나누며, 독립된 여러 에이전트가 협업하는 구조는 아닙니다.

## 만드는 과정과 실행 흐름
1. 서비스의 분석·기획 흐름을 먼저 구현했습니다. 사용자별 행동의 순서와 집계 기준을 코드로 확정했습니다.
2. 외부에 전송할 범위를 좁혔습니다. 원본 행동 기록과 식별자를 제외하고 집계 숫자, 익명화한 집단, 자료 구분, 품질 점검 숫자, 사용자가 입력한 목표만 전달합니다.
3. 서버가 인원 순서·방문 유무·목표 길이를 검사하고 완료율과 이탈 인원을 계산합니다. 계산 결과에 f0~f7 근거 번호를 붙입니다.
4. OpenAI Responses API로 세 가지 가설, 근거 번호, 주요 지표, 비교 방법, 중단 조건과 자료 한계를 요청합니다. JSON이라는 정해진 자료 형식으로 답하도록 합니다.
5. 코드가 필수 항목과 근거 번호를 검사합니다. 잘못된 답이면 검토 호출 전에 중단합니다.
6. 같은 모델의 별도 호출로 원인 확정, 없는 수치, 가상 자료의 실제 성과화, 지표 불일치를 검토합니다. 보류이면 반영 버튼을 차단합니다.
7. 사람은 근거와 한계를 확인하고 ‘내 기획에 반영’을 누릅니다. 기존 기획을 보관하고 세 가설과 실험 초안을 반영합니다. 점수는 모두 1로 초기화하며 선택 이유와 최종 기준은 사람이 씁니다.

입력 조건이 실행 중 변경되면 해당 결과의 반영을 차단합니다. 선택 이유를 자동으로 써 주지 않습니다. 가설의 원인이나 효과를 증명하지 않고 실험 실행, 고객 연락, 배포도 수행하지 않습니다.

## 왜 이렇게 결정했나
기획·데이터 분석 포트폴리오에서 중요한 것은 화려한 답변보다 자료 기준과 판단 근거입니다. 계산은 재현 가능한 코드로 처리하고 AI는 미검증 가설과 계획 초안에 사용합니다. 같은 모델의 자기 검토만으로 정답을 보장할 수 없어 코드 검사와 사람 확인을 함께 둡니다. SDK나 별도 에이전트 프레임워크 없이 Node.js 기본 기능과 HTTP 요청으로 구현해 흐름을 직접 설명할 수 있게 했습니다.

## 비용·상태·보관
한 번 실행하면 정상 흐름에서 외부 API를 두 번 호출합니다. 단계별 60초 제한, 동시 실행 1개, 서버 실행 세션 기준 시간당 최대 5회입니다. 서버 재시작 시 한도 기록은 초기화되므로 계정 전체 지출 한도를 대신하지 않습니다. 자동 재시도는 없습니다. 실행 시 실제 모델명·시각·합계 처리량·검토 결과를 보여줍니다. 채택한 결과만 분석 상태와 보고서에 보관합니다.

`store:false`로 API 응답 저장을 요청하지 않습니다. 이것이 모든 사업자 로그의 즉시 삭제나 완전한 개인정보 보호를 보장하는 뜻은 아닙니다. 사용자가 목표란에 쓴 내용은 전송되므로 개인 정보나 비밀을 적지 않아야 합니다. 키는 서버의 `.env`에만 보관하며 정적 파일 허용 목록으로 외부 접근을 차단합니다.

## 검증과 남은 확인
자동 검증에서 외부 응답을 시험용 응답으로 대체해 생성→검토, 잘못된 근거, 검토 보류, 인증 실패 등을 검증합니다. 2026-10-01 실제 OpenAI 호출을 가상 자료로 두 차례 실행했습니다. 첫 제안의 개입·지표 불일치를 별도 검토가 발견해 반영을 차단했고, 목표를 명확히 지정한 두 번째 제안은 검토를 통과했습니다. 실제 자료·실사용자·개선 실험 효과도 확인하지 않았습니다. 기능 시험에서 세 가설의 관찰 근거 표시·검토 보류 차단·검토 통과 후 반영을 확인했습니다. 사용자는 본인 목표로 결과를 읽고 최종 선택과 실험 기준을 결정해야 합니다.

공식 근거: [구조화 출력](https://developers.openai.com/api/docs/guides/structured-outputs), [Responses API](https://developers.openai.com/api/docs/guides/text).
