# 제품 개선 실험실 / Product Lab

사용자 행동을 분석하고, 개선안 하나를 선택한 뒤 검증할 실험을 기획하는 웹서비스입니다. 기획과 데이터 분석을 연결하는 최종 프로젝트의 첫 버전입니다.

## 해결하려는 문제
차트를 확인한 뒤 무엇을 바꿀지 결정하고, 그 결정을 어떻게 검증할지 문서로 연결하기 어렵습니다. 이 서비스는 관찰 → 가설 비교 → 사람의 선택 → 실험 계획을 한 화면에서 연결합니다.

## 현재 사용할 수 있는 기능
- 온라인 클래스 신청 과정의 가상 자료로 전체·모바일·데스크톱 분석
- 단계별 진행률·이탈 인원·전체 신청 완료율 계산
- 직접 인원 입력 및 역순·음수·분수·범위 검증
- 개선 가설 3개의 영향·근거 확신·노력 평가, 가설별 별도 계획 작성
- 진행률 증가를 가정한 시뮬레이션 (실제 효과 예측이 아님)
- 브라우저 내부 저장과 기획 보고서 Markdown 내려받기

**AI는 아직 연결되지 않았습니다.** 예시 가설은 사람이 작성한 내용이며 AI 출력으로 표시하지 않습니다. 실제 고객 데이터, 로그인, 데이터 파일 업로드, 실험 배정·실행·통계적 효과 검정은 이번 버전에 포함되지 않습니다.

## 실행
Node.js가 있는 컴퓨터에서 이 프로젝트 폴더의 터미널에 `npm start`를 입력하고 http://127.0.0.1:4178 에 접속합니다. 추가 패키지 설치는 필요하지 않습니다. 종료는 실행한 터미널에서 Ctrl+C입니다.

검증은 `npm test`입니다. 이탈·완료율·집단 분석, 모순된 데이터, 0명, 점수 범위, 시뮬레이션 계산을 확인합니다.

## 화면에서 확인할 것
1. 처음 실행하면 가상 예시로 방문 1,200명·완료율 12.0%·최대 이탈 504명이 보입니다.
2. 모바일을 선택하면 방문 840명·완료율 7.5%로 바뀝니다.
3. 개선안 선택 후 이유와 가설을 작성합니다. 다른 가설로 바꿨다가 돌아오면 각 초안이 유지됩니다.
4. 계획을 저장하고 새로고침해 유지 여부를 확인합니다.
5. 보고서를 내려받아 자료 구분·선택 이유·실험 준비 상태를 확인합니다.

## 데이터 정의와 해석 한계
- 같은 기간·같은 집단에서 순서대로 단계에 도달한 고유 인원입니다. 예시 기기 집단은 서로 겹치지 않는다고 가정합니다.
- 진행률 = 다음 단계 인원 / 현재 단계 인원. 이탈 인원 = 현재 단계 인원 - 다음 단계 인원. 전체 완료율 = 신청 완료 인원 / 방문 인원.
- 가장 큰 이탈 구간은 **인원** 기준입니다. 최대 이탈 비율 구간과 다를 수 있습니다. 동률은 먼저 나온 구간을 표시합니다.
- 분모가 0이면 ‘계산 불가’를 표시합니다. 직접 입력 자료의 출처·중복·기간 일치는 자동 확인하지 않습니다.
- 차이가 있다는 사실만으로 원인을 단정하지 않습니다. 개선 가설을 인터뷰·관찰·비교 실험으로 검증해야 합니다.
- 시뮬레이션은 선택 단계 진행률만 증가하고 이후 진행률·유입 인원은 유지된다고 가정합니다. 진행률 상한은 100%이며 결과는 반올림한 인원입니다. 계산에 필요한 진행률이 없으면 결과를 표시하지 않습니다.
- 점수 = 영향 × 근거 확신 / 노력. 각 1~5의 주관적 평가입니다. 예시 점수는 검증된 근거가 아닙니다.

## 기획 결정과 이유
1. 서비스의 계산 기능을 먼저 제작: AI가 만든 문장과 실제 계산 값을 비교할 기준을 마련하기 위해서입니다.
2. 첫 주제는 온라인 클래스 신청: 네 단계의 사용자 행동으로 관찰과 개선 가설을 쉽게 설명하기 위한 기본값입니다. 사용자 조사를 거쳐 선택된 분야는 아닙니다.
3. 표준 HTML·CSS·JavaScript 사용: 현재 규모에는 추가 패키지가 없어도 작동하며, 계산 부분을 독립적으로 시험할 수 있습니다.
4. 사람의 선택을 보존: AI의 추천과 별개로 사용자가 선택 이유를 기록하도록 설계했습니다.
5. 가상 자료와 효과 검증을 구분: 계산 예시를 실제 성과로 소개하지 않기 위해서입니다.

## 다음 제작 단계: AI 에이전트
실제 자료의 입력 방식과 개인정보 처리 범위를 정한 뒤, 서버에서 AI를 연결합니다. API 키(외부 서비스를 사용할 때 제시하는 비밀 인증값)는 브라우저 코드나 공개 저장소에 넣지 않습니다.

에이전트의 목표는 자료 품질 점검 → 검증된 계산 결과 읽기 → 근거에 연결된 개선 가설 제안 → 단정·계산 오류 점검 → 사람이 선택할 후보 제출입니다. 단순 채팅 기능보다 이 작업 흐름과 실패 기록을 검증하는 데 집중합니다. 현재 이 흐름은 기획이며 실행되지 않습니다.

## 저장과 공개 제출
입력 내용은 이 브라우저의 저장 공간에만 남습니다. 같은 주소에서 사용하는 다른 사람이 볼 수 있고, 브라우저 자료 삭제로 사라질 수 있습니다. 중요 계획은 보고서로 내려받으세요. 새 자료로 분석을 시작하면 현재 저장 내용을 교체하므로 이전 계획은 먼저 내려받으세요. 기록을 여러 개 관리하는 기능은 후속 범위입니다.

GitHub는 소스 코드와 설명을 보관하고 공유하는 서비스입니다. 공개 제출 대상으로 준비한 폴더는 이 폴더이며, 상위 실습 폴더 전체를 공개하지 않습니다. 아직 GitHub 저장소 생성·공개·웹 배포는 수행하지 않았습니다. 공개 전 실제 개인 자료·비밀 인증값 포함 여부를 확인해야 합니다.
