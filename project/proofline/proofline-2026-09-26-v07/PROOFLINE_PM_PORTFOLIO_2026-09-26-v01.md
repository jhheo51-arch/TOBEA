# PROOFLINE — PM 포트폴리오 사례 초안

상태: **개념·시제품 단계 / 실제 이용자 검증 전**  
역할: 참가자가 문제·대상·서비스 방향과 주요 수정 의견을 제시했고, Codex가 문서와 시제품 구현을 도왔습니다. 코드를 혼자 개발한 프로젝트로 소개하지 않습니다.

## 1. 어떤 문제를 풀고 싶었나

참가자는 자신의 경험이나 강점을 가지고도 이를 **누구에게 어떤 도움으로 설명하고 어떻게 알릴지** 모르는 사람이 많다는 문제를 제기했습니다. 소상공인뿐 아니라 진로·활동·개인 브랜딩을 고민하는 사람을 도울 방법을 찾고자 했습니다.

문제의 빈도와 심각성은 아직 실제 이용자 조사로 확인되지 않았습니다.

## 2. 제품 가설

사람의 이야기를 듣고 경험의 근거에서 강점을 찾아, 가능한 방향을 함께 고르면 자기소개·첫 활동·알릴 이야기를 더 쉽게 정할 수 있을 것입니다. 한 번 정리한 뒤 실제 행동과 반응을 기록해 다시 고치는 과정을 포함합니다.

**첫 시험 대상:** 경험은 있지만 자신을 설명하고 첫 활동을 정하기 어려운 개인. 전체 서비스의 대상을 이 집단으로 영구히 제한하지는 않습니다.

## 3. 중요한 제품 결정

| 시점 | 관찰 또는 참가자의 의견 | 결정 |
| --- | --- | --- |
| 초기 | 브랜딩 기획·마케팅 대행 등 사업 관심이 있었음 | 실제 경험을 한 문장과 첫 제안으로 정리하는 PROOFLINE 시작 |
| 방향 수정 | 소상공인에 한정하고 싶지 않고 유료화는 나중에 다루고 싶었음 | 개인의 진로·활동·브랜딩까지 대상 확장, 가격 기능 우선순위 하향 |
| 이용 흐름 수정 | 경험을 서비스로 만드는 일과 자신을 알리는 일을 함께 적용하고 싶었음 | 별도 경로를 하나의 강점 → 방향 → 자기소개·첫 활동 흐름으로 통합 |
| 화면 피드백 | 가상 사례 시연에서 기존 디자인이 바뀌었다는 피드백 | 기존 PROOFLINE 시각 구성을 다시 적용 |
| 기능 피드백 | 상단 ‘가상 사례 보기’로 이동했을 때 결과가 비어 보였음 | 예시 자동 표시, 두 진입 버튼 연결, 텍스트 결과 제공 |

이 표의 화면 피드백은 참가자와의 협업에서 나온 내용입니다. 외부 고객 다수의 관찰 결과가 아닙니다.

## 4. 만들어 본 것

[PROOFLINE v06 시제품](index.html)은 상담 내용을 구조화합니다. 실제 경험과 강점 근거, 관련 자료의 출처, 선택지 2개와 이유, 자기소개, 작은 첫 활동과 알릴 이야기, 행동 후 반응과 수정 이력을 한 사람의 카드 버전으로 보여줍니다. [가상 사례](fictional-case.txt)는 화면 작동을 설명하기 위한 허구입니다.

상담자가 내용을 판단하고 작성하며, 웹은 이를 정리·보관합니다. AI가 진로 적합성이나 사실을 자동 판정하지 않습니다.

## 5. 현재 결과와 한계

- **확인됨:** 시제품 코드의 기본 흐름 검사, 가상 사례 카드 생성, 사용자의 방향·디자인·진입점에 대한 수정 의견 반영
- **아직 확인 전:** 처음 쓰는 이용자의 이해도, 실제 이용자의 첫 행동, 상담 결과의 효과, 반복 이용, 지불 의사
- **검사가 더 필요한 것:** 로컬 파일에 대한 브라우저 자동 접근이 차단돼 실제 클릭 화면은 직접 확인하지 못함

따라서 이 사례의 성과를 “사용자의 진로를 개선했다”거나 “사업 수요를 검증했다”고 쓰지 않습니다.
