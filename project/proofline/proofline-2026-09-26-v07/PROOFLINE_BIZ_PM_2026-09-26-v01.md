# PROOFLINE: 사업 실험과 PM 포트폴리오 방향

작성일: 2026-09-26 · 상태: 실제 이용자 검증 전 의사결정 초안  
여기서 PM은 **제품 기획자(Product Manager)**를 뜻한다고 가정합니다.

## 한 줄 판단

**지금 PROOFLINE은 사업으로 검증된 서비스보다, 문제를 정의하고 시제품을 고친 PM 프로젝트에 더 가깝습니다.** 다음에는 화면 기능을 늘리지 않고 실제 사람 5명과 작은 무료 실험을 합니다. 그 결과는 사업 가능성을 판단하는 자료이자 PM 포트폴리오의 핵심 증거가 됩니다.

## 현재 확인된 것과 부족한 것

| 구분 | 현재 확인된 것 | 아직 모르는 것 |
| --- | --- | --- |
| 문제 | 창업자가 생각하는 문제와 가상의 이용 흐름, 참가자의 진로 상담 경험 | 같은 문제를 실제로 겪는 사람이 얼마나 있는지 |
| 제품 | 로컬 시제품, 근거·방향·자기소개·첫 행동·반응 수정의 기록 기능 | 처음 쓰는 사람이 혼자 이해하고 쓸 수 있는지 |
| 가치 | 가상 사례의 한 장 카드 | 실제 사람이 자기 말 같다고 느끼고 행동으로 옮기는지 |
| 사업 | 상담자가 함께 작성하는 서비스 형태의 가설 | 고객을 만날 경로, 반복 가능한 시간·품질, 추후 유료 의사 |
| PM 역량 | PRD와 v02~v06 변경 과정, 사용자 피드백에 따른 수정 | 실제 고객 조사·우선순위 결정·결과 측정 자료 |

화면의 완성도만으로 사업성이 입증되지는 않습니다. [Y Combinator는 프로젝트를 사업으로 발전시키려면 실제 사용자와 이야기하며 원하는 것을 확인해야 한다고 설명합니다](https://www.ycombinator.com/blog/from-student-side-project-to-startup). [Atlassian은 제품 기획자의 주요 역할로 고객 이해, 전략, 우선순위, 결과 확인을 설명합니다](https://www.atlassian.com/agile/product-management).

## 사업으로 발전시키는 순서

### 1. 첫 시험 대상만 좁히기

전체 비전은 소상공인에 한정하지 않습니다. 첫 시험은 **경험은 있지만 자신을 어떻게 소개하고 첫 도움으로 만들지 막막한 개인** 5명에게 집중합니다. 같은 고민이 실제로 반복되는지 보기 위한 임시 범위입니다.

### 2. 서비스 한 번의 약속을 명확히 하기

무료 시범 범위: **45분 이야기 듣기 → 강점과 근거 확인 → 한 장 방향 카드 작성 → 7일 뒤 첫 행동·반응 확인**. 진로를 대신 결정하거나 마케팅 성과를 약속하지 않습니다. 상담 전후에 운영자에게 들어간 시간도 기록합니다.

### 3. 세 가지 신호만 보기

1. **이해:** 참여자가 카드를 자기 말로 설명할 수 있는가?
2. **행동:** 7일 안에 카드의 첫 행동을 실제로 해보는가?
3. **반복 가능성:** 1명당 대화·자료 조사·수정에 얼마나 시간이 드는가?

5명 중 4명이 자기 말로 설명하고, 2명 이상이 첫 행동을 하는지를 **임시 판단 기준**으로 둡니다. 작은 표본이므로 수요나 효과를 확정하는 숫자로 사용하지 않습니다. 반응이 약하면 화면을 더 만들기 전에 질문과 대상부터 고칩니다.

### 4. 유료화는 반응 뒤에

반복되는 문제와 결과가 확인되면 1:1 진단, 후속 실행 도움, 소규모 교육 중 무엇을 요청하는지 확인합니다. 가격·결제·온라인 마케팅 대행·디자인·IT 중개는 현재 결정하지 않습니다. 이는 참가자가 유료화를 추후에 다루겠다고 한 우선순위를 따릅니다.

## PM 포트폴리오로 만드는 방식

포트폴리오의 제목 가설: **“경험을 설명하지 못하는 개인을 위한 강점 기반 방향 카드: 문제 정의부터 반응 후 수정까지”**

| 보여줄 장면 | 지금 쓸 수 있는 근거 | 추가해야 할 근거 |
| --- | --- | --- |
| 왜 시작했나 | 참가자가 관찰한 자기소개·브랜딩의 어려움, 창업자 배경 | 실제 참여자의 자기 말로 된 문제 |
| 누구의 문제인가 | 대상 가설과 PRD의 변화 | 첫 5명 중 반복되는 상황·차이 |
| 무엇을 우선했나 | 두 경로를 하나로 통합, 유료화 연기, 가상 사례 기록 | 실제 이용자 반응에 따라 버린 기능과 선택 이유 |
| 무엇을 만들었나 | v02~v06 화면과 기능, 가상 사례 | 사용 과정에서 막힌 지점과 수정 전후 |
| 무엇을 배웠나 | 질문이 보이지 않았던 경험, 디자인 변경 피드백, 가상 사례 보기 빈 화면 피드백 | 실사용자의 이해·행동·재사용 여부 |

현재까지의 사용자 피드백은 **참가자 한 사람의 제품 방향·화면 관련 피드백**입니다. 이를 다수 고객 조사나 매출 성과처럼 쓰지 않습니다. 가상 사례 역시 기능 시연으로만 표시합니다.

포트폴리오에는 예쁜 화면만 나열하지 말고 **문제 → 가설 → 선택 → 만든 것 → 실제 관찰 → 다음 결정**을 한 페이지에 연결합니다. PM의 일은 무엇을 왜 만들지 판단하는 일이라는 [Atlassian의 설명](https://www.atlassian.com/agile/product-management)과도 맞습니다.

## 지금 한 단계

첫 시범 대화에 참여할 **실제 사람 1명**을 정합니다. 그분에게 “지금 자신을 설명하거나 다음 활동을 정할 때 어디에서 막히는지”부터 묻고, 대화 전에는 PROOFLINE 화면을 보여주지 않습니다. 실제로 겪은 문제를 먼저 듣는 방법은 [Y Combinator의 사용자 관찰 가이드](https://www.ycombinator.com/blog/practical-design-user-observation/)와도 맞습니다. 이름과 사적인 내용은 동의 없이 포트폴리오에 싣지 않습니다.
