# PROOFLINE v07 — 이야기 → 방향 → 실행 후 수정

`index.html`을 열면 가상의 박다은 사례가 바로 보입니다. 상단 **가상 사례 보기**를 누르면 언제든 다시 열 수 있습니다. 오른쪽 카드 위의 1차·2차 버튼으로 첫 제안과 반응을 반영한 수정을 비교합니다. 화면 결과가 보이지 않으면 [`fictional-case-v07.txt`](fictional-case-v07.txt)를 확인합니다.

## 새 기록을 직접 써보는 순서

1. **새 기록 시작**을 누르고 1단계에서 가명, 고민, 직접 해본 일을 적어 **이야기 저장**을 누릅니다. 강점과 진로 방향은 아직 몰라도 됩니다.
2. **2. 강점·방향**에서 상담자와 함께 경험의 근거, 강점 가설, 가능한 방향, 자기소개, 첫 행동을 정리합니다. **첫 방향 카드 저장**을 누릅니다. 돌아볼 날짜는 7일 뒤로 제안되지만 바꿀 수 있습니다.
3. 첫 행동 후 오른쪽 **첫 행동 결과 기록**을 누릅니다. 실제 행동과 반응 또는 아직 못 한 이유와 다음 행동을 적고 저장합니다. 같은 사람의 새 카드 버전으로 남습니다.

카드는 **본인 진술**, **상담자의 해석**, **외부 자료**를 구분해 표시합니다. 외부 자료는 사용자가 넣은 출처·확인 날짜를 표시하며, 앱이 자료의 내용이나 경험의 사실 여부를 검증하지는 않습니다. 본인은 강점 해석에 동의하거나 수정이 필요하다고 표시할 수 있습니다.

**이 카드 저장**은 현재 버전만, **전체 이력 저장**은 해당 사람의 모든 카드 버전을 텍스트 파일로 저장합니다. 기록은 이 브라우저에 저장되고 자동 알림·계정 동기화는 없습니다. 기존 v05/v06의 이 브라우저 기록을 읽어올 수 있지만, 원래 저장 데이터는 지우지 않습니다. 가격·결제는 아직 포함하지 않습니다.

가상 인물, 경험, 반응은 모두 허구입니다. 산업 참고 자료만 [한국지능정보사회진흥원 고령층 디지털 교육 사례](https://www.nia.or.kr/site/nia_kor/ex/bbs/View.do?bcIdx=28573&cbIdx=99938&parentSeq=28573)를 사용했습니다. 이 자료는 가상 인물의 적합성이나 사업 수요를 입증하지 않습니다.

검사: `node --check script.js`, `node check.cjs`. 로컬 파일에 대한 브라우저 자동 클릭·렌더링 검사는 실행 환경의 보안 정책으로 수행하지 못했습니다.
