# PROOFLINE AI 기회발견 에이전트 — 콘셉트 v01

작성일: 2026-10-01 · 상태: 조사와 설계. 현재 비공개 사이트에는 아직 AI 호출 기능이 없습니다.

## 문제

현재 결과 요약은 이용자가 입력한 경험·강점·대상·제안을 한데 모읍니다. 입력에 없던 고객의 문제, 대안, 시장 신호, 반론, 검증 방법을 발견하지 못합니다. 새 기능의 목표는 **“내 경험으로 누구의 어떤 문제를 어떤 방식으로 풀 수 있나?”에 대해 근거 있는 새로운 선택지를 제안하는 것**입니다.

위 기능들은 각 서비스의 공식 설명을 참고한 것입니다. PROOFLINE의 제품 방향과 예시는 별도 기획 가설입니다.

## 제안: 기회발견 에이전트 한 개

1. **경험을 파고듭니다.** 직접 한 행동, 실제 들은 반응, 원하는 일의 조건, 아직 모르는 점을 구분하고 가장 중요한 추가 질문 1~2개를 합니다.
2. **밖을 살핍니다.** 사용자가 정한 고객 유형에 대해 공개 자료에서 반복 문제, 이미 있는 대안, 접근 가능한 채널을 조사합니다. 자료마다 링크와 확인 날짜를 남깁니다.
3. **다른 관점 세 가지를 만듭니다.** 같은 경험을 개인 대상 도움, 조직 대상 도구, 교육·콘텐츠 등 서로 다른 서비스 형태로 바꿔 봅니다. 각 제안에 “왜 떠올렸는지”와 “왜 실패할 수 있는지”를 함께 씁니다.
4. **첫 실험 하나를 고릅니다.** 사용자의 강점·자원·빠른 실행 가능성에 맞춰 우선순위를 추천하되, 고객 수요가 확인됐다고 주장하지 않습니다. 7일 안에 확인할 행동, 질문, 성공·중단 신호를 제안합니다.
5. **제안을 연습하고 고칩니다.** AI가 잠재 고객 역할로 질문하거나 거절해 보고, 이용자가 제안 문구를 수정합니다. 실제 연락과 공개는 이용자가 결정합니다.

## 박다은 창작 사례에서 기대하는 새 인사이트 예시

입력: “모바일 예약 순서를 설명한 적이 있다.” 가상의 1차 제안에 관한 반응 두 건 중 한 건이 인증 문자 단계에서 막혔다.

**AI 가설:** 개인에게 전체 예약을 다시 설명하는 것 외에, 도서관 직원이 반복해서 만나는 ‘인증 문자 찾기’ 순간을 위한 작은 안내 도구를 만들 수 있습니다. 같은 설명을 여러 직원이 재사용할 수 있다는 점에서 조직 대상 제안도 후보입니다. 이는 고객 수요나 구매 의사가 확인된 결론이 아닙니다.

- 대안 A: 이용자 한 명에게 10분 안내
- 대안 B: 도서관 직원용 ‘막히는 단계 확인표 + 설명문 한 장’
- 대안 C: 가족이 대신 설명할 때 쓰는 안내문
- **다음 실험:** 실제 담당자 2명에게 어떤 단계에서 질문을 가장 자주 받는지 묻고, 기존 안내문이 있는지 확인합니다. 답을 듣기 전에는 B가 우월하다고 결론 내리지 않습니다.

## 화면에서 보여줄 것

기존 결과 요약 위에 **“AI가 발견한 기회”**를 별도 영역으로 둡니다. 각 카드에는 ①새 관점 ②내 경험 근거 ③외부 조사 근거 ④반대 근거·미확인점 ⑤이번 주 실험을 표시합니다. `확인된 사실 / AI의 해석 / 검증 전 가설`을 눈에 띄게 구분합니다. 출처가 없으면 ‘외부 근거 미확인’으로 남깁니다.

## 첫 구현 범위와 완료 기준

- 본인 기록이나 창작 사례를 입력으로 받아 서로 다른 기회 가설 3개를 제안합니다.
- 각 가설에는 원래 기록의 근거와 확인하지 못한 부분이 명시됩니다.
- 외부 조사를 사용할 때는 출처 링크·확인 날짜·인용된 주장 범위를 보여줍니다. 찾지 못한 자료를 만들어 쓰지 않습니다.
- 한 가설을 선택하면 작은 서비스 범위와 첫 검증 행동이 생깁니다. AI가 실제 고객에게 자동 연락하지 않습니다.
- 창작 사례는 끝까지 시연으로 표시하며 실제 이용·시장 검증 수치에 넣지 않습니다.

## 판단 기준

기존 입력 문장을 순서만 바꿔 보여주면 실패입니다. 사용자가 예상하지 못한 **대상·문제·전달 방식의 새로운 조합**이 나와야 하고, 왜 그런 제안을 했는지와 틀릴 가능성을 설명할 수 있어야 합니다.
