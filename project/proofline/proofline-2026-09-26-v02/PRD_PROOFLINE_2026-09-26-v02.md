# PROOFLINE v02 제품 기획서

작성일: 2026-09-26 · 상태: 유료 고객 검증 전 초안

## 1. 한 줄 정의

**전문성은 있지만 이를 팔 수 있는 제안으로 설명하기 어려운 1인 전문가와 초기 사업자에게, 짧은 진단 대화와 5일 설계를 통해 첫 유료 서비스의 대상·약속·납품 범위를 정리해 주는 기획 스튜디오.**

웹 시제품은 상담의 입구이자 내부 상품 설계 도구입니다. 웹에서 결제하거나 고객 정보를 서버에 보내지는 않습니다.

## 2. 창업자 배경과 판단

참가자가 직접 말한 강점은 **빠른 기획, 빠른 사고 전환, 설득력 있는 말하기**입니다. 사주에서 제안받은 브랜딩 기획, 온라인 마케팅 대행, 디자인·IT 외주 중개, 전문 교육·상담은 사업 방향을 떠올린 계기입니다. 이 적성이 실제 구매와 수익으로 이어진다는 증거로 보지는 않습니다.

따라서 첫 상품은 창업자가 직접 잘할 수 있는 **진단·제안 설계**에 둡니다. 마케팅 운영, 제작 연계, 교육은 고객 문제가 반복되고 납품 체계가 검증된 뒤 순서대로 확장합니다. 네 가지를 동시에 상시 대행하면 운영 범위와 선지출이 커져 소자본 목표와 충돌할 수 있다는 **운영 가설**입니다.

## 3. 고객 문제와 첫 대상

첫 고객 가설: 특정 분야의 경력·사례는 있으나 자신을 소개하고 유료 상품을 만들기 어려운 독립 준비 전문가, 코치, 강사, 1인 사업자.

고객이 하려는 일: “나는 누구의 어떤 문제를, 어떤 방식으로 해결하고, 얼마의 범위를 납품하는가?”를 한 장으로 설명하고 첫 유료 상담을 받아 봅니다.

제외 대상: 당장 광고 집행량만 늘리고 싶은 기업, 실적 보장을 요구하는 고객, 의료·법률·투자 등 자격이나 별도 규제가 필요한 판단을 대신 맡기려는 고객.

## 4. 현재 자료에서 확인한 것과 아직 모르는 것

- 크몽에는 [1회 브랜딩 상담과 월간 마케팅 관리](https://kmong.com/gig/101258), [퍼스널 브랜딩 코칭](https://kmong.com/gig/513382) 상품이 실제로 게시되어 있습니다. 이는 유사한 **공급 형태가 존재한다는 관찰**일 뿐, PROOFLINE의 수요·적정 가격·수익성을 증명하지 않습니다.
- 온라인 마케팅 대행으로 확장할 때는 조회수만 보고 성과를 주장하지 않습니다. [네이버 광고주센터](https://ads.naver.com/help/faq/1648)는 광고 후 특정 행동을 전환으로 측정하는 기능을 안내합니다. 실제 서비스에서는 문의·예약 등 고객과 합의한 행동을 기준으로 측정할 계획입니다.
- 고객 인터뷰, 유료 구매, 재구매, 실행 파트너의 품질과 비용은 아직 확인하지 않았습니다.

## 5. 차별화와 상품 순서

핵심 약속: **그럴듯한 이름만 붙이는 브랜딩이 아니라, 실제 경험을 근거로 첫 판매 제안과 납품 범위를 정리한다.** 매출·광고 성과는 보장하지 않습니다.

| 순서 | 상품 | 가설 가격·결제 방식 | 정해진 결과물 | 시작 조건 |
| --- | --- | --- | --- | --- |
| 1 | 60분 문제 진단 | 19만 원, 예약 전 결제 가설 | 문제 우선순위와 다음 행동 1장 | 잠재 고객 인터뷰에서 문제 확인 |
| 2 | 5일 오퍼 설계 | 79만 원, 착수 전 50%·납품 시 50% 가설 | 발견 인터뷰 1회, 브랜드 문장·첫 상품 소개서 각 1장, 수정 1회 | 진단 고객이 구체적 납품을 요청 |
| 3 | 2주 콘텐츠 실험 | 고객별 범위 확정 후 견적 | 채널 1개, 기획 4개, 회고 1회 | 첫 제안과 측정할 행동이 합의됨 |
| 4 | 디자인·IT 제작 연계 | 범위·파트너 비용 확인 후 견적 | 요구사항, 파트너 비교, 일정·검수 | 검증된 파트너와 서면 범위 확보 |
| 확장 | 90분 소규모 워크숍 | 유료 파일럿으로 가격 검증 | 참가자별 오퍼 초안 | 1:1 상담에서 반복 문제 발견 |

가격은 판매 제안용 **실험값**이며 시장 평균이나 권장 가격이 아닙니다. 고객 반응과 실제 투입 시간을 보고 수정합니다.

## 6. 현금 회전 설계

목표는 무조건 선결제를 늘리는 것이 아니라, **짧고 명확한 납품, 회수 시점 합의, 착수 전 직접비 통제**로 현금 부담을 줄이는 것입니다.

1. 진단은 예약과 결제를 함께 제안합니다. 취소·환불 조건을 사전에 명확히 고지합니다.
2. 설계 상품은 범위와 수정 횟수를 합의한 뒤 착수합니다. 잔금 수령일을 납품 조건에 적습니다.
3. 외주 제작은 고객 대금, 파트너 비용, 지급 시점이 확정되기 전 착수하지 않습니다. 제작 품질과 고객 커뮤니케이션의 책임 주체도 정합니다.
4. 모든 건에서 `착수 시 수령액 − 착수 전 직접비`, `계약금액 − 직접비`, `잔금 수령까지 기간`, `대표자 투입시간`을 따로 봅니다. 계약금액에서 직접비만 뺀 값은 순이익이 아닙니다.

예: 79만 원 계약, 착수 전 50% 수령, 직접비 10만 원이면 착수 시 39.5만 원을 받고 그중 직접비를 빼면 29.5만 원이 남습니다. 이 숫자는 세금·수수료·본인 노동·환불을 제외한 예시입니다.

## 7. 사용자 흐름

### 잠재 고객

1. PROOFLINE에서 자신의 고객, 해결할 문제, 방식, 실제 사례를 입력합니다.
2. 브랜드 문장과 첫 서비스 초안을 봅니다. 부족한 증거는 빈칸으로 표시합니다.
3. 결과를 복사하거나 텍스트 파일로 저장합니다.
4. 실제 유료 상담을 원한다면 별도 안내 채널에서 문의합니다. **현재 시제품에는 문의·예약·결제가 연결되어 있지 않습니다.**

### 창업자

1. 네 가지 서비스 방향 중 하나를 골라 납품 항목, 제외 범위, 검증 질문을 확인합니다.
2. 가격·선수금·직접비·기간을 바꾸며 착수 전 현금 부담을 살펴봅니다.
3. 고객별 실제 계약에서는 웹의 예시 숫자 대신 합의된 범위를 문서로 작성합니다.

## 8. v02 기능 요구사항과 완료 기준

| 기능 | 완료 기준 |
| --- | --- |
| 브랜드 초안 | 기존 질문에 답하면 문장·사례·첫 상품·검증 질문이 나오고, 빈 근거를 임의로 만들어내지 않음 |
| 서비스 방향 4종 | 선택할 때 상품 설명, 납품 범위, 제외 범위, 다음 검증이 바뀜 |
| 상담 제안 멘트 | 선택한 상품에 맞는 짧은 설명이 나타나며 복사할 수 있음 |
| 현금 흐름 계산 | 가격·선수금 비율·직접비·기간·잔금 지연·대표자 투입시간을 바꾸면 착수 시 현금, 직접비 차감액, 잔금까지의 기간, 투입시간당 금액이 즉시 갱신됨 |
| 입력 오류 | 음수, 100% 초과 선수금, 빈칸 등 잘못된 값에는 계산값 대신 안내 표시 |
| 데이터 | 브랜딩 입력은 현재 브라우저에만 저장; 고객 정보를 서버나 외부 AI에 전송하지 않음 |
| 접근성 | 입력에 보이는 이름이 있고 키보드로 버튼을 사용할 수 있으며 작은 화면에서 가로 스크롤이 없어야 함 |

현재 문장 생성은 **미리 정한 문장 규칙**으로 작동합니다. 실제 고객의 고유한 강점을 깊이 해석하거나 근거를 검증하는 AI 기능은 아닙니다. 사람의 상담과 검토가 유료 서비스의 핵심입니다.

## 9. 첫 4주 검증 계획

| 기간 | 할 일 | 판단 기준 초안 |
| --- | --- | --- |
| 1주 | 대상 후보 10명과 문제 인터뷰 | 5명 이상이 같은 막힘을 자신의 말로 설명하는지 |
| 2주 | 시제품을 보여 주고 60분 진단 제안 | 실제 결제 2건 이상 또는 거절 이유 기록 |
| 3주 | 진단 결과를 납품하고 오퍼 설계 제안 | 유료 설계 요청 1건 이상, 대표자 투입시간 기록 |
| 4주 | 가격·범위·결제 시점 조정 | 선지출 초과 건 0건, 잔금 지연 원인 파악 |

이 수치는 실행을 위한 **임시 판단 기준**이지 시장 예측이 아닙니다. 모집 채널·고객군이 바뀌면 기준도 다시 정합니다.

## 10. 주요 위험과 다음 버전

- **범위 팽창:** 상담 때 요청한 모든 일을 받아들이면 납품이 길어집니다. 제안서에 결과물·수정 횟수·제외 항목을 적습니다.
- **증거 부족:** 고객의 경험을 성과처럼 과장하지 않습니다. 확인 가능한 사례와 추정 효과를 분리합니다.
- **외주 품질:** 디자인·IT 제작은 검증된 파트너, 책임 범위, 비용·일정 합의 전에는 판매하지 않습니다.
- **고객 정보:** 서버에서 문의를 받는 기능을 추가할 때는 필요한 정보, 이용 목적, 보유기간 등을 먼저 정하고 관련 안내를 마련합니다. 현재 로컬 시제품에는 서버 수집 기능이 없습니다. [개인정보보호위원회 안내서 목록](https://pipc.go.kr/np/cop/bbs/selectBoardList.do?bbsId=BS217&etc1=%ED%98%84%EC%9E%AC+%EC%95%88%EB%82%B4%EC%84%9C&mCode=G010030020)
- **다음 버전:** 유료 고객의 실제 질문과 납품 자료가 3건 이상 쌓인 뒤 문의·예약, 제안서 작성, 프로젝트 진행 현황을 순서대로 검토합니다.
