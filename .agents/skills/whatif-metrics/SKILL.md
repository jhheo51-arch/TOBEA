# Whatif 비교 지표 설정

사건의 실제 변화와 사용자가 나중에 제시할 가정을 같은 기준으로 비교할 수 있도록 지표를 설계한다. 한국어 존댓말로 답한다.

## 설계

- 현재 질문과 사실 확인 자료를 먼저 읽는다. 없는 사실 확인 결과를 만들어내지 않는다. 미확인 전제는 조건부로 남기고, 필요한 경우 해당 사실만 확인한다.
- 무엇을 누구와 언제 비교할지 정한다. 기본은 핵심 지표 2~3개이며 분석 질문에 따라 조정한다.
- 자료 확보 여부와 지표의 유용성을 함께 검토한다. 조회 수를 인지도나 호감도 자체라고 부르지 않는 등, 대신 측정하는 수치는 무엇을 설명하지 못하는지도 적는다.
- 출연 전후 비교에는 다른 활동·계절성·동시 사건, 스포츠 비교에는 출전 기회·대체 선수·상대 조건, 역사 비교에는 사료의 범위와 상충 여부를 검토한다. 관련되는 조건만 적용한다.
- 비율은 분자·분모를 정의하고 규모가 다른 대상을 단순 총량으로 비교하지 않는다. 결측값을 0으로 바꾸지 않는다. 비교 집단의 차이와 선택 편향을 설명한다.
- 타당한 수치가 없으면 질적 비교 항목을 제안한다. 역사적 통제력 등을 근거 없이 점수화하지 않는다.

## 출력

먼저 분석 질문·대상·기간·비교 기준을 한 단락으로 적는다. 다음 항목으로 지표 정의표를 만든다.

| 지표 | 무엇을 보여주는가 | 계산식·단위 | 기간·대상·비교 기준 | 자료 출처·확보 상태 | 해석 한계 |
|---|---|---|---|---|---|

자료 확보 상태는 ‘실제 확인 / 자료 위치만 확인 / 미확보’를 구분한다. 측정 기준 설계와 실제 계산 완료를 구별한다. 관측값 계산을 요청받으면 자료 범위 안에서 수행하고 식과 근거를 남긴다.

마지막에는 사용자가 채울 입력 항목만 제안한다. 예를 들어 ‘가정 이름 / 바꿀 조건 / 조건의 근거 / 예상 결과 / 불확실성’이며, 사용자가 제공하지 않은 값·예측·확률·교훈을 채우지 않는다. 기본값을 만들어 사실상 결과를 대신 정하지 않는다.

발행 글의 조회·구독 같은 운영 성과는 사건의 비교 지표와 분리하고 요청받은 경우에만 설계한다. 대시보드 요청에는 기존 data-analytics:build-dashboard 스킬을 안내한다. 시각화에 넘길 때 관측값과 사용자 추정값을 구분하고, 사용자 가정이나 계산 규칙이 없으면 추정 영역은 미입력으로 둔다.

결과 저장은 프로젝트 규칙에 따라 새 파일로 하고, 다음 단계는 요청받은 범위에만 진행한다.
