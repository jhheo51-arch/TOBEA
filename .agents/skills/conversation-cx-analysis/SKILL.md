# 대화 자료에서 고객경험 개선 가설 만들기

사용자가 공개 대화 자료를 기반으로 고객경험을 조사하거나 개선 방향을 찾고자 할 때 사용한다. 유튜브 댓글의 수집·최신순·인기순 표본 판단에는 `youtube-comment-analysis`를 함께 사용한다.

## 읽기 전 기록

- 자료가 붙은 원문 콘텐츠 또는 서비스 상황, 댓글을 쓰게 만든 공지·이벤트·질문을 먼저 확인한다. 직접 확인하지 못한 화면·음성·운영 결과는 확인했다고 쓰지 않는다.
- 분석할 사람, 그 사람이 경험하는 접점·단계, 분석자가 실제 바꿀 수 있는 요소, 이번 질문을 먼저 정한다. 공개 댓글 작성자를 모두 고객으로 단정하지 않는다.
- 분석 단위와 범위를 밝힌다. 댓글·작성자·대화·사건 중 무엇을 세는지 정하고, 수집 시각·채널·정렬·중복 처리·제외 대상을 기록한다. 수집 표본의 빈도를 전체 고객 비율처럼 쓰지 않는다.
- 언어별로 실제 읽고 해석할 수 있는 범위를 확인한다. 규칙이나 번역 근거가 없는 언어는 원문을 보존하고 직접 검토 대상으로 남긴다.

## 해석의 네 층

1. **관찰:** 반복 표현, 구체적 행동, 요청, 불편, 반례를 원문 근거와 함께 묶는다. 한 문장에 여러 주제가 있을 수 있다.
2. **맥락:** 원문 콘텐츠·고객 여정의 어느 지점에서 나온 반응인지 연결한다. 공지나 이벤트가 유도한 반응은 별도로 표시한다.
3. **욕구 후보:** 그 반응으로부터 사용자가 하려는 일이나 해결하려는 문제를 문장으로 적는다. 관찰을 욕구의 확정 사실로 바꾸지 않는다.
4. **다음 제공물:** 운영자가 실제 바꿀 수 있는 안내·콘텐츠·기능·절차 중 작은 변경을 제안하고, 성공 여부를 확인할 행동 지표를 붙인다.

## 우선순위와 출력

- 건수 하나로 순위를 매기지 않는다. 행동의 구체성, 서로 다른 표본에서의 재현, 원문 맥락과의 일치, 반례, 변경 가능성을 함께 비교한다.
- 결과마다 `확인한 사실 → 가능한 해석 → 다음에 제공할 것 → 작은 시험 → 확인할 지표`를 구분한다. 가장 먼저 시험할 것 하나와 이유를 제시하고, 실제 효과가 확인되기 전에는 성과를 단정하지 않는다.
- 사람이 다시 판단할 수 있도록 짧은 근거 인용과 출처를 남긴다. 공개 배포용 결과에는 작성자 식별 정보나 불필요하게 긴 원문을 넣지 않는다.
- 자동 분류를 수정할 때는 원래 라벨과 사람이 고른 라벨, 근거·반례 판단, 이유를 별도로 남긴다. 수정된 건수와 자동 집계 건수를 섞지 않는다.
- 같은 사례를 다시 수집하면 원문·수집 시각·표본 범위를 시점별로 보존한다. 댓글이나 주제의 증감은 관찰로 기록하고, 실제 변경·전후 지표·다른 설명을 확인하기 전에는 개선 효과라고 쓰지 않는다.
