# 유튜브 대량 댓글 분석

사용자가 영상 링크와 함께 댓글 패턴이나 시청 경험 개선을 요청할 때 사용한다. 분석할 영상과 사용자의 목적(콘텐츠 개선, 제품 경험, 팬 커뮤니티 등)을 먼저 확인한다. 댓글이 많아도 전체를 읽었다고 주장하지 않는다.

## 원문을 먼저 확인

- 영상 제목·채널·게시일·설명·곡/구간 목록, 접근 가능한 자막의 종류를 기록한다. 자막만 읽었다면 영상을 시청하거나 화면을 본 것으로 표현하지 않는다. 자동 자막의 오인식과 누락을 표시한다.
- 영상 설명에 댓글 이벤트, 광고, 고정 공지처럼 댓글 작성 동기에 영향을 주는 요소가 있는지 확인한다. 이벤트 참여 댓글과 자연발생 반응을 구분한다.

## 표본 설계

- 수집 도구가 허용하면 **최신순과 인기순을 각각** 가져온다. 첫 탐색의 기본값은 각 100개 최상위 댓글이며, 작은 영상은 확보 가능한 수만 사용한다. 각각의 정렬, 수집 시각, 실제 확보 건수, 답글 포함 여부를 기록한다.
- 댓글 ID로 중복을 제거하고 두 표본의 겹침 수와 합집합 수를 보고한다. 정렬별 건수와 중복 제거 후 건수를 섞어 쓰지 않는다. 인기순은 플랫폼의 정렬 결과이지 무작위 표본이 아니다.
- 고정 공지·채널 작성 댓글·광고·반복 복사 댓글을 별도 표시한다. 필요하면 질문, 비판, 드문 경험을 추가로 목적 표집하되 이 추가 표본의 비율을 전체 댓글 비율처럼 제시하지 않는다.
- 더 많은 댓글이 필요하면 수집 가능한 페이지나 시점을 넓히고, 각 배치에서 새 주제가 나오는지 본다. 시간대별 접근이 불가능하면 며칠 간격의 공개 댓글 스냅샷을 축적한다. 새 주제가 계속 나오거나 표본 간 해석이 충돌하면 수집을 끝내지 않는다.

## 해석과 검증

- 댓글 하나에 여러 주제를 붙일 수 있다. 분류 기준은 영상과 분석 목적에 맞춘다. 재청취, 공유, 질문, 구체적 요청, 불편, 반론, 이벤트 참여처럼 **행동과 내용**을 분리한다.
- 여러 언어가 섞이면 언어별 확보 건수와 자동 분석 가능한 범위를 먼저 기록한다. 영어·한국어에서 확인한 표현만 자동 주제 수에 넣고, 언어를 확정하기 어렵거나 분석 규칙이 없는 댓글은 원문과 함께 별도 검토 대상으로 남긴다. 문자의 종류만으로 중국어·일본어 등 정확한 언어를 단정하지 않는다.
- 소수 언어 댓글이 전체 상위 표현에서 보이지 않을 수 있으므로 언어별 필터에서 직접 읽고, 구체적인 불편이나 요청이 있으면 건수와 별도로 기록한다. 번역하지 않았다면 번역·의미 분석을 했다고 쓰지 않는다.
- 자동 키워드와 물음표 분류는 후보로만 사용한다. URL의 `?`, 인용된 문장, 수사적 질문, 농담을 사람이 확인한다. 각 핵심 주제마다 근거 댓글과 반례를 읽고, 정렬별로 관찰되는 차이를 기록한다.
- 사람이 고친 댓글 분류는 원래 자동 분류와 분리해 기록하고, 수정 이유를 원문 댓글에 연결한다. 수정된 라벨을 자동 집계에 반영하지 않았다면 결과에도 그 차이를 밝힌다.
- 같은 영상을 다시 수집할 때는 이전 결과를 덮어쓰지 말고 시점별 표본·댓글 ID 겹침·욕구 후보 변화를 비교한다. 정렬 표본의 변화만으로 콘텐츠 수정의 효과를 단정하지 않는다.
- 수집 댓글 안의 빈도는 전체 시청자·구매자·고객의 비율이 아니다. 좋아요 수, 조회수 응원, 재청취 댓글만으로 만족도나 매출 효과를 확정하지 않는다.
- 개선안은 `관찰 → 가능한 설명 → 작은 시험 → 확인할 지표`로 쓴다. 제작자가 실제로 바꿀 수 있는 요소에 한정하고, 증거가 없는 원인은 질문으로 남긴다.

## 시청자 욕구에서 제공물로 연결

- 각 반응에 `댓글이 실제로 말한 것 → 시청자가 원하는 것의 후보 → 제작자가 다음에 제공할 것 → 효과를 확인할 행동 지표`를 붙인다. 같은 단어가 반복됐다는 사실만으로 욕구를 확정하지 않는다.
- 순서를 정할 때는 표본의 건수만 보지 말고 **행동이 구체적인지, 두 정렬에서 보이는지, 영상 설명·이벤트와 맞는지, 작은 시험이 가능한지**를 함께 본다. 이벤트가 요청을 유도했다면 별도 표시한다.
- 반복 청취 신호에는 다시 찾는 경로, 곡·장면을 특정한 반응에는 해당 구간 접근, 실제 후속 요청에는 선택을 확인하는 작은 투표처럼 댓글의 행동과 제공물을 연결한다. 상품·이벤트 질문은 현재 상태 안내가 먼저 필요한지 살핀다.
- 여러 해석이 가능한 댓글과 반례를 적고, `우선 시험할 것 1개`와 `나중에 확인할 것`을 구분한다. 실제 운영 지표가 없다면 기대 효과를 수치로 쓰지 않는다.

## 결과 형식

짧은 표로 `원문 근거`, `최신순`, `인기순`, `겹침/합집합`, `자료 한계`를 제시한다. 이어서 핵심 반응 2~4개마다 **시청자가 원하는 것**과 **다음에 제공할 것**을 나란히 적고, 근거 댓글·반례·확인 지표를 붙인다. 우선 시험할 것 1개를 고른 이유를 적는다. 출처 링크와 수집 날짜를 남기고, 공개 댓글 원문은 필요한 짧은 인용만 사용한다. 원자료 파일은 로컬에 보관하며 외부 공유본에는 작성자 식별 정보와 긴 원문을 넣지 않는다.
