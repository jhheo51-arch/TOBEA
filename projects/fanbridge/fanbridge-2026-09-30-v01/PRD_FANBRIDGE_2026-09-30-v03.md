## 1. 목적과 첫 결과물

삼성 팬의 구체적인 질문을 근거로 문제 하나를 고르고, 작은 안내와 응대 기준을 바꾼 뒤 실제 팬 시험에서 무엇이 달라졌는지 설명한다.

첫 사례는 **분석용 표·재현 가능한 코드 + 팬 안내 시제품 + 응대 가이드 + 실제 시험 기록 + 포트폴리오 사례 문서**로 완성한다. 시제품은 핵심 사용 흐름을 시험할 수 있는 작은 화면이다. 자료를 분석하는 운영자 웹앱은 첫 사례 완료 뒤 필요성을 검토한다.

핵심 흐름: 자료·정책 확인 → 후보 비교 → 문제 하나 선택 → 안내·응대 기준 개선 → 실제 시험 → 결과·실패 사례 해석.

## 2. 대상과 후보 범위

구단은 삼성 라이온즈, 홈구장은 대구 삼성라이온즈파크(라팍)로 고정한다. 홈·원정, 적용 연도, 판매처를 구분한다.

| 후보 | 관련 팬·상황 | 이번에 바꿀 수 있는 것 |
|---|---|---|
| A. 멤버십·선예매 — 먼저 검증 | 삼성 홈경기 구매를 준비하며 회원 자격·선예매 조건을 이해하려는 팬 | 조건 확인 질문, 용어 풀이, 다음 행동, 공식 근거와 문의처 |
| B. 첫 직관 — 조건부 전환 | 예매를 마친 초행자가 방문을 준비해 라팍 좌석에 도착하기까지 | 준비·이동·입장·좌석 도착 안내 중 확인된 막힘 하나 |

A가 우선인 이유는 이미 조건 이해에 관한 공개 질문을 탐색했고 공식 확인 경로가 있기 때문이다. 가장 많은 문의 분야로 입증됐다는 뜻은 아니다. A를 선택해도 멤버십 구매·선예매·좌석·환불 전체를 동시에 만들지 않고, 검증 가능한 조건 하나 또는 밀접한 조건 묶음으로 좁힌다. 좌석 가격은 선택한 과제에 필요한 경우에만 포함한다.

B는 예매 방법·굿즈·관람 후 경험을 첫 범위에 추가하지 않는다. 예매 완료부터 좌석 도착까지도 넓으므로 현장에서 확인된 막힘 하나를 선택한다. 굿즈 배송·교환은 기존 탐색 후보로 보존하되 이번 두 후보 비교에서 제외한다.

## 3. 문제 구분과 후보 선택 기준

| 문제 구분 | 확인할 질문 | 가능한 대응 |
|---|---|---|
| 정보를 못 찾음 | 어디에서 무엇을 찾았고 어느 지점에서 멈췄는가? | 위치·경로·표현 개선 |
| 문장을 이해하지 못함 | 안내를 본 뒤 어떤 조건·행동을 잘못 이해했는가? | 조건 분기·예시·용어 풀이 |
| 정책 자체의 문제 | 안내를 정확히 이해해도 해결되지 않는 제약인가? | 정책 개선 제안. 안내 시험과 성과를 분리 |

두 후보를 다음 네 기준으로 비교하고 `확인된 근거 / 미확인 / 불리한 근거`와 출처를 남긴다. 근거 없는 점수 합계로 선택하지 않는다.

1. 관련 고객 모집 가능성: 실제 해당 상황을 경험했거나 준비하는 팬을 모집할 경로가 있는가?
2. 실제 문제 근거: 구체적 행동·막힘이 공개 질문 또는 동의받은 조사에서 확인되고 반례도 검토됐는가?
3. 공식 정답 확보: 기준일·회원 유형·경기·판매처 또는 방문 조건을 고정해 정답을 만들 수 있는가?
4. 안내 개선으로 해결 가능한 정도: 우리가 바꾸는 문장·경로·화면이 그 막힘에 직접 대응하는가?

A의 정답·자료·참가자 확보가 어렵거나 B의 근거가 더 강하면 같은 FANBRIDGE 안에서 B로 전환한다. 전환 이유와 버전을 기록하고, 시험 시작 전에 문제·정책·과제를 확정한다. 두 후보 모두 검증 조건을 충족하지 못하면 근거 부족으로 표시하고 팬 조사부터 보완한다. 실제 참가자가 없는데 합성 자료로 효과 검증을 대신하지 않는다.

## 4. 자료와 분석 방법

2025·2026년 자료를 문제 발견과 정책 맥락 이해에 활용한다. **연도별 비교와 연도별 100건 확보는 첫 사례 완료의 필수 조건이 아니다.** v02의 100건 목표는 연도 비교를 별도로 확장할 때 참고할 목표로 보존한다.

필수 분석은 다음을 포함한다.

- 분석 단위는 독립된 공개 질문·경험 기록이다. 답글은 원 질문에 연결하고 재게시·동일 URL 중복은 별도로 표시한다.
- 검색어·채널·기간·정렬·수집일·포함 및 제외 이유를 기록한다. 광고, 선수 경기력 평가, 서비스 경험과 무관한 글은 제외한다.
- 문제 유형, 관람 단계, 적용 조건을 복수 분류할 수 있다. 기록 수와 주제 수를 구분하며 주제 비율의 합이 100%를 넘을 수 있음을 표시한다.
- 자동 분류를 쓰면 원래 분류·사람 수정·수정 이유를 보존한다. 자동화 없이 사람이 분류해도 같은 근거 기록을 남긴다.
- 원문 맥락, 짧은 근거, 반례, 다른 설명을 함께 검토한다. 관찰·해석·미확인을 구분한다.
- 공개 질문만으로 고객센터 문의량·팬 전체 비율·실제 해결 여부를 추정하지 않는다. 제목만 공개된 비밀글은 본문 분석에 합치지 않는다.

자료의 양보다 선택한 문제의 맥락과 검증 가능성을 우선한다. 소수 사례라면 사례 탐색이라고 명시한다. 수집 규모와 부족한 근거를 보고하되 특정 건수만 넘으면 문제를 입증했다고 판단하지 않는다.

보조 연도 비교를 수행할 때는 2025/2026 각각 1월 1일~9월 29일, 같은 채널·검색 기준·주제·시즌 맥락을 우선한다. 현재 접근 가능한 과거 자료는 당시 전체 자료의 복원이 아니다. 삭제·검색 노출·공지 변화 등 다른 설명을 함께 기록한다. 조건을 맞출 수 없으면 사례별 맥락만 비교하고 경험의 개선·악화나 빈도 증감 순위를 주장하지 않는다. 비교를 하지 못해도 현재 문제와 안내 효과를 검증하면 첫 사례는 완성할 수 있다.

## 5. 공식 정책과 API 사용

API는 외부 서비스에서 자료를 가져오는 연결 통로다. 첫 사례는 확인한 자료를 표로 정리해 진행할 수 있으며 API 연결을 필수로 만들지 않는다.

- 삼성·판매처의 공식 문서로 기준일·적용 기간·회원 유형·구매처·조건을 확인한다. 과거 정책과 현재 정책을 섞지 않는다.
- 커뮤니티 답변은 문제 발견 근거다. 답변을 공식 정답으로 자동 채택하지 않는다.
- 시험 정답을 확정할 때 사용한 공지·약관·화면의 버전과 확인일을 남긴다. 정책이 바뀌면 영향과 재검증 필요성을 기록한다.
- 네이버 검색 API는 자료 발견 보조 후보다. 전체 과거 본문·댓글을 제공한다고 가정하지 않는다. 스포츠·기상 API는 선택한 문제에 필요한 경우에만 검토한다.
- YouTube 자동 분석은 이용 범위·보관·파생 데이터 조건 확인 전 비활성으로 둔다. 비밀글·로그인 제한은 우회하지 않는다.
- 실제 인증 호출·계약 권한·시즌별 반환 자료는 아직 확인하지 않았다. 이전 API 조사 문서는 확인 당시의 참고 자료이며 연결 시 다시 검증한다.

## 6. 첫 실행 산출물과 완료 기준

| 산출물 | 필수 내용 | 완료 기준 |
|---|---|---|
| 분석용 표·코드 | 출처·날짜·맥락·중복·분류·수정·제외·근거·반례 | 같은 입력과 기준으로 집계 재현, 누락·미확인과 실제 0건 구분 |
| 후보 비교·문제 정의 | A/B 네 기준 비교, 선택 이유, 바꿀 요소 | 선택 문제 하나와 공식 정답·관련 팬 확보 상태를 설명할 수 있음 |
| 팬 안내 시제품 | 상황·조건 확인 → 다음 행동 → 공식 근거·문의처 | 선택한 문제의 정상·조건 차이·예외 과제를 수행할 수 있음 |
| 응대 가이드 | 필수 확인 질문·표준 답변·예외 전달 기준 | 시제품과 동일한 정책·조건을 사용하고 위험한 단정을 피함 |
| 시험 계획·기록 | 동의·배정·과제·정답·시간·도움 요청·중단·버전 | 실제/합성 분리, 익명 기록, 판정 근거와 분모 확인 가능 |
| 사례 문서 | 문제·분석 과정·선택·변경·시험 결과·실패·기여·한계 | 실제 인원과 비율을 함께 제시하고 미측정은 미측정으로 표시 |

운영자 웹앱의 파일 가져오기·탐색·분류 수정·연도 비교·과제 관리·내보내기는 후순위다. 현재는 표·코드·문서로 수행한다. 로컬 데이터베이스도 필수로 요구하지 않는다.

## 7. 안내 시제품의 흐름

A의 예시: 적용 기준일과 회원 유형 확인 → 선택한 선예매 조건 질문 → 가능한 다음 행동 → 공식 근거·맞는 문의처.

B로 전환할 경우: 예매 완료 확인 → 선택한 방문 단계·필요 조건 확인 → 다음 이동·입장 행동 → 공식 근거·예외 도움.

두 흐름은 동시에 구현하지 않는다. 팬 화면에 분석 코드·API 설정 등 판단에 필요 없는 구현 정보를 넣지 않는다. 공식 삼성 서비스로 오인되지 않게 개인 CX 실습임을 표시한다.

## 8. 실제 팬 조사와 시험

준비 조사에서는 동의받은 관련 팬 5명 이상 인터뷰를 목표로 한다. 최근 실제 질문, 찾아본 안내, 막힌 단계, 받은 답으로 행동할 수 있었는지를 확인한다. 아직 모집한 인원이 아니다. 초행자 후보는 가능하다면 동의받은 현장 관찰로 맥락을 보완하되 현장 관찰을 수행했다고 미리 쓰지 않는다.

본 시험은 관련 팬 총 20명, 기존 안내 10명·개선 안내 10명을 목표로 한다. 탐색적 소규모 시험이며 통계적 검정력 계산으로 정한 인원은 아니다.

- 선택한 문제와 관련된 경험·자격을 모집 기준에 명시한다. 조건에 따라 회원 종류 또는 첫 방문·반복 방문 경험의 균형을 맞추고 그 안에서 무작위 배정한다.
- 같은 참가자는 한 안내 조건만 수행한다. 두 조건은 같은 과제·기기 조건·정책 버전·제한 시간(과제당 5분)을 사용한다.
- 정상 상황·조건 차이·예외 상황의 대표 과제 3개를 준비한다. 시험 전에 정답·부분 정답·오답 및 위험한 오답 기준을 확정한다.
- 기존 조건은 검증된 공식 안내, 개선 조건은 같은 정책을 바탕으로 바꾼 안내다. 원본과 개선본의 정확한 화면·버전을 보존한다.
- 익명 참가자 ID·동의·모집 경로·경험·배정·답·시간·도움 요청·중단 사유를 기록한다. 중단자는 전체 배정 인원에서 삭제하지 않는다.
- 기술 장애는 사전 정의한 사유로 구분하고 포함·제외 결과를 함께 확인한다. 실제 모집 규모가 달라지면 계획과 차이를 공개하며 목표 인원을 채웠다고 쓰지 않는다.
- 정책·정답·시제품을 확정하지 못한 상태에서는 효과 비교 시험을 시작하지 않는다.

## 9. 성과 지표와 보고 방식

| 지표 | 정의 | 잠정 목표 |
|---|---|---|
| 자가 해결 성공률 | 추가 도움 없이 3개 과제를 모두 제한 시간 내 정답으로 해결한 참가자 / 전체 배정 참가자 | 개선 조건이 기존보다 20%포인트 높음 |
| 도움 요청 | 한 번 이상 도움을 요청한 참가자 수 / 전체 배정 참가자 | 개선 조건에서 낮아짐 |
| 해결 시간 | 성공자의 해결 시간 중앙값, 전체 완료·중단·시간초과 수 병기 | 성공률 저하 없이 성공자 중앙값 20% 단축 |
| 위험한 오답 | 잘못된 구매·입장 행동 등을 유도하는 답의 건수 / 전체 제출 답 수 | 안내의 정책 오류 0건, 팬 위험 오답 증가 없음 |
| 응대 품질 | 정확성·조건 확인·다음 행동·예외 전달의 사전 기준 충족 여부 | 정확성 필수 항목 전부 충족 |

20%포인트는 예를 들어 40%에서 60%로 바뀐 차이다. 조건별 10명에서는 한 명이 10%포인트에 해당하므로 **성공 인원/배정 인원, 비율, 실패·중단 사례를 함께 제시**한다. 이는 설명 예시이며 실제 결과가 아니다.

목표는 달성한 성과가 아니다. 목표를 넘지 못해도 왜 실패했는지 근거와 다음 개선을 남기면 사례를 완성할 수 있다. 소규모 모집 결과는 참여자 범위에서 해석하고 시간 단축만으로 전체 고객 경험 개선을 주장하지 않는다.

예매·구매·상담 운영 기록이 없으므로 성과는 “시험에서 자가 해결·도움 요청·시간이 어떻게 달라졌는가”로 표현한다. “삼성 고객센터 문의를 줄였다”는 표현은 실제 운영 기록을 확보해 검증하기 전 사용하지 않는다. 2025/2026 자료 차이도 안내 개선 효과로 해석하지 않는다.

## 10. 실행 순서와 역할

1. 멤버십·선예매의 공식 정답·구체적 질문·참가자 모집 가능성 확인. 첫 직관도 같은 네 기준으로 비교한다.
2. 문제 하나 확정. 관련 자료를 정리·분류하고 근거·반례·원인 후보와 변경 범위를 기록한다.
3. 안내 시제품과 응대 가이드, 기존 안내, 과제·정답·시험 계획을 제작·검토한다.
4. 동의받은 실제 팬을 모집·배정하고 시험한다. 인원·비율·시간·실패 사례를 함께 분석한다.
5. 문제 선택부터 변경·결과·한계까지 포트폴리오 사례로 정리한다. 운영자 웹앱 확장은 이후 판단한다.

Codex는 자료 정리·분석 코드·문서·시제품 제작을 수행한다. 사용자는 접근 가능한 팬 모집 경로와 참여 동의 확보를 함께 진행하고 결과를 확인한다. 모집이나 메시지 발송이 필요해지면 구체적으로 요청하며 사용자 지시 없이 타인에게 연락하지 않는다. 사람의 정책 검토·팬 모집·시험을 자동으로 완료했다고 기록하지 않는다.

## 11. 완료와 범위 제외

기획·시제품 준비 완료는 문제 하나의 근거·정답·후보 선택 이유, 분석용 표·코드, 안내·응대 가이드, 시험 계획이 갖춰진 상태다. **첫 사례 완료는 실제 시험과 결과·실패·한계 문서화까지 수행한 상태**다. 효과 검증 전 문서는 미측정으로 표시한다.

연도 비교를 못해도 첫 사례를 완성할 수 있다. 목표 효과를 달성하지 못해도 시험 결과를 정직하게 보고하면 사례를 완성할 수 있다. 실제 시험이 없으면 준비 단계로 남긴다.

첫 범위에서 제외: 운영자 웹앱, 전체 구단 통합, 실시간 고객센터 대행, 자동 환불·보상, 경기 취소 예측, 상담 인력 배치, 구매 이력 기반 예측, 검증되지 않은 자동 답변, 공개 게시. 비밀 인증값·개인 식별 정보는 결과물에 포함하지 않는다.

## 12. 채용 역량과 남길 증거

기존 공고 조사의 연결은 유지하되 결과물 규모를 줄인다. 공고 근거와 접근 한계는 v02의 §2에 보존되어 있으며 신규 채용시장 분석은 이번 수정에서 수행하지 않았다.

| 보여줄 역량 | 첫 사례의 증거 |
|---|---|
| 고객 문제 정의 | 찾기·이해·정책 문제 구분, 실제 질문·반례 |
| 신뢰할 수 있는 분석 | 수집 기준·중복·복수 분류·사람 수정·누락 기록 |
| 우선순위 판단 | 두 후보의 네 기준 비교와 선택·전환 이유 |
| 개선 실행·운영 연결 | 안내 전후, 응대 기준, 예외 전달 |
| 성과 측정·문서화 | 실제 배정·성공 인원·비율·시간·실패·한계·본인 기여 |

단독 프로젝트라면 단독으로 기록한다. 개인 프로젝트가 회사 경력·상담 조직 운영 경험을 대체한다고 표현하지 않는다.

## 13. 현재 확인된 상태

확정: 삼성 대상, FANBRIDGE 유지, A 우선 검증·B 조건부 전환, 첫 산출물 축소, 연도 비교 보조, 실제 시험 중심 성과 표현.

확인됨: 삼성 공개 질문의 초기 탐색과 공식 공지 접근 경로. 충분한 표본·세부 정책 정답·실제 참가자 확보를 뜻하지 않는다.

남은 확인: 좁힐 조건 하나, 공식 정답과 기준일, 관련 고객 모집 경로·인원, 추가 근거·반례, 안내 제작·실제 시험. 다음 단계는 **멤버십·선예매의 검증 가능성을 네 기준으로 확인하는 것**이다.
